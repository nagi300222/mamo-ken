## B. Input 10 / 12 / 24F

Current values:

- `BAL.BUF = 10`: normal attack input buffer (`f.bufF = BAL.BUF`).
- `BAL.CMD.buffer = 12`: command pre-input hold when recovery/stun remaining frames are within 12F.
- `BAL.CMD.bufF = 24`: two-direction command input history window.
- `BAL.FLICK_MS = 300`: flick time threshold.
- `BAL.JUST_TAP_MS = 100`: just tap threshold.

Conclusion: the ledger phrase “10F = tap/flick allowance” does not match current code naming. In current code, 10F is normal attack buffering, while tap/flick use millisecond thresholds.

## E. Roar

Current constants: `BAL.ROAR = { s:16, armor:14, a:4, r:24, d:130, stun:34 }`.

Current behavior:

- Startup: 16F.
- Contact frame: `pf === BAL.ROAR.s + 1`.
- Active: single contact check through `roarStriking`.
- Recovery: 24F after startup/active.
- Armor: `phase === 'roar' && pf <= BAL.ROAR.armor`.
- Armor is a duration property, not a one-hit-consumed field.
- Armor damage multiplier: incoming strike damage is halved while roar armor is active.
- Guard damage/chip uses special guard constants: guard damage 45 and chip 20.
- Clean hit means not guarded and not absorbed by opponent roar armor; clean hit grants Ult +1.
- Roar-vs-roar applies clean-hit-like damage to both and grants Ult +1 to both.
- KO can be immediate for normal roar resolution; roar-vs-roar chooses side 0 if both hit 0 in current code path.

No T00 fix is applied for v0.12 candidate values.

## F. S Gauge

Current `BAL.SG`: `aHit=12`, `aHitC=[12,7,4]`, `aBlk=8`, `whiff=2`, `gOk=6`, `got=5`.

Character S multipliers:

- `moguzo = 1.00`
- `pisuke = 1.25`
- `godan = 0.90`

Observed gain paths:

- Attack hit: combo-indexed `aHitC` / `aHit` through `gainS`.
- Attack blocked: attacker gains `aBlk`; defender gains guard success/focus paths.
- Whiff: attacker gains `whiff` when attack/cmdAtk ends without hit.
- Guard success: `gOk` path exists in guard resolution.
- Got hit: `got` path exists in hit resolution.
- Grab hit: attacker gains fixed amount 10 through `gainSAmt`.
- Roar consumes S to 0 on start; clean hit grants Ult, not S.
- Gyuiin current implementation grants winner S +30.
- Round reset preserves S/Ult/Focus except first round.

## G. Gyuiin / Clash legacy differences

Current Gyuiin values:

- Base damage: 120.
- Streak bonus: +30 per consecutive win after first.
- Winner S Gauge: +30.
- Winner Ult: +1.
- Loser hitstun: 40F after clash.
- `pendKO` defers KO until clash ends.
- Online sends minigame decisions/taps/hits as `mgPick`, `mgTap`, and `mgHit` through lockstep commands.

Difference from v2.7 current target noted for later task: S +30, streak bonus, and guaranteed 40F follow-up stun are current legacy behavior and are not changed in T00.

## H. Down / Wake / Round

Current `BAL.DOWN`: `downF=45`, `wakeF=20`, `followupMul=0.5`.

- Down allows one follow-up hit at 0.5 multiplier.
- After follow-up, additional down/wake hits are ignored by `handleIfDowned`.
- Wake is 20F invulnerable, then returns to idle/queued command resolution.
- `roundInit(false)` resets HP/guard/phase/buffers and `clashStreak`; S/Ult/Focus are preserved across rounds except `first` initialization.

## I. KO / Time Up

- Direct hit/grab/roar can call `startKO` immediately.
- Gyuiin and Ult set `B.pendKO` and resolve KO after the cinematic/clash flow exits.
- KO flow sets loser phase `ko`, winner phase `win`, then `finishRound` after 120F.
- HP-equal Time Up increments both wins. If both reach required wins, result is `DRAW`; otherwise it can produce WIN/LOSE if only one side reaches the target.
- During non-fight flows normal fight input is not processed.

## J. Existing 9 command moves

The 9 current command moves are serialized in `reports/current_impl_constants.json` under `commandMoves`. Existing 3 moves per character remain current implementation slots 1-3.

## K. CPU / PRNG

- Battle PRNG uses `mulberry32` / `rng()`.
- Offline battle seed uses `Date.now()` at start; online battle uses shared seed from room start.
- CPU observations read public current combat state such as opponent phase, `pf`, `atkLv`, guard/down/dizzy state, and S/Ult/Focus state.
- Online fight path uses `netFightStep` and does not call `aiStep`.
- `Math.random` occurrences are visual/audio/select-only in current source: audio noise, spark variation, CPU opponent selection on select screen, and camera shake. The audit script reports all occurrences for review.

## L. Pose / Asset

- `POSE_IDS` includes S1-S6 style runtime pose IDs plus `cmd1`, `cmd2`, `cmd3`.
- `poseId(f)` maps current phases to pose IDs.
- S6 connection is represented by runtime pose IDs `crouch`, `sway`, `lunge`, `crouch_atk` and the current sprite loader.
- Sprite height and portrait ratio are current BAL data and serialized in JSON.
- Assets are not changed by T00.

## M. Online sync

- Server relays battle payloads; client lockstep owns simulation.
- `NET.localQ` / `NET.peerQ` store delayed per-frame commands and hold state.
- `NET.matchSeq` prevents stale command messages from previous matches contaminating a new match.
- `netLogicTick` only advances simulation once both local and peer inputs for `NET.simF` exist.
- Online Gyuiin uses `mgPick`, `mgTap`, `mgHit` through the same lockstep path, so the stale comment risk is documented as current implementation relying on actual synchronized minigame input.
- No state hash or replay system exists in current implementation.

## N. Save

`localStorage` references are absent in current runtime source. Save schema / keys / persistent settings are therefore not implemented in the audited current implementation.
