# 04｜文字・色・余白・空間・グラフィックの設計

**本章の数値はFigmaと720×320のWebで実測して決める暫定値。商品規格でも本人の承認値でもない。**

## 04-1 座標系
- 論理キャンバス：横持ちの720×320を低い限界の主試験、852×393、もう一段大きい画面も検証。
- 物理端末：ノッチ/safe areaを除いた実表示領域で配置し、左右両指が中央を覆わない領域を求める。
- 戦闘の**中央3D舞台**は現在の固定400px幅を正としない。キャラ同士の距離/接触点/弾道が読める面積を先に決め、タッチHUDをその上で再構成する。
- 横画面の物理iPhoneと、ブラウザをCSS回転した横表示、Simulatorの縦framebufferは別条件。
- 拡大や可変文字と重なっても、どの場面もCTAと戻る操作を失わないこと。

## 04-2 タイポグラフィ候補
| 文体階層 | 暫定サイズ（CSS px） | 主な用途 | 注意 |
|---|---:|---|---|
| T-01 超大見出し | 36〜64 | 対戦モード・勝利の瞬間 | 文字が読めるよりも場面を感じる役 |
| T-02 表示名 | 26〜36 | 選択キャラ、結果、勝者 | 名前が長い場合に縮小しすぎず折返し/省略代替 |
| T-03 主操作ラベル | 16〜22 | 開始・戻る・決定・主要攻撃 | 指の近くで読み取れること |
| T-04 重要HUD数字 | 22〜38 | タイマー・ラウンド・HP比など | 等幅の数字を適用 |
| T-05 基本文 | 14〜17 | 設定・技表・ルールなど | 読む行動のある画面のみ |
| T-06 補助 | 12〜14 | 選択中の得意/苦手・状態補助 | 戦闘中は読ませず形・数字で代替を検討 |
| T-07 一時/非重要ラベル | 11〜12 | 二次ステータス・デバッグ | 11以下を常時の重要情報に使わない |
- フォント案：見出しは商用利用可の太め日本語ゴシックから実機比較。本文はOS依存フォントより表記の安定する日本語Sansを第一候補。WebのFigma再現のため実フォント名をトークン化。**権利と配信サイズを確認するまで確定しない。**
- 日本語と英数の読み順：名前、固有技、ラベルは日本語の短さを主として、英語を装飾的な二重説明にしない。
- 文字の階層は原則**3種類までを同一場面で強く主張**。必要な情報が多いなら場所を分ける。

## 04-3 配色体系と意味
**装飾上のパレット候補**：
- A 拳祭：背景深緑 #17291F／生成り #F8E4B9／火の琥珀 #F1A65B／深緑面 #324A34。
- B 山嶺：競技背景 #101C23／白寄り #F4F7F5／シアン #4AE6CF／青い面 #243B43。
- C 絵巻：深い茶 #3A3029／紙色 #FAEBD7／暖い金 #F3C88F／木の面 #685441。

**意味色は画面に依存して勝手に変えない**：
- HP・危険・Drive・奥義・選択・無効・成功・警告は意味IDを固定し、A/B/Cの装飾パレットと混同しない。
- Driveをたまたま「水色が綺麗」という理由だけでHPの色へ流用しない。
- 色だけで重要状態を識別しない。枠・形・ゲージ分割・テキスト・動作の差を併用する。

## 04-4 余白とグリッド
- 4pxグリッドを基礎。間隔候補は4/8/12/16/24/32。これは**実体の論理ピクセル**の仮案。
- 異なる意味の要素は線で区切る前に、塊と余白の差で見せる。
- カードや枠線は「タップ可能」「ひとまとまり」「比較対象」を教える時だけ使う。装飾のための罫線乱用を禁止。
- 大きな立ち絵/3Dを置く前に名前の領域を確保。アートが文字を押し出す構図は可変名で再検証。
- セーフエリアを装飾板のサイズで隠さない。タップ可能領域は最終実機のポイント/ピクセル換算で検証。

## 04-5 画面のリズム
静→動→静の対比を意識する。
- モード選択：選択中の場面が少し強調、未選択は静。
- キャラ選択：顔/名前/構えが変化。切替のたび派手な全画面フラッシュを出さない。
- Battle：HUDは安定、攻撃時はキャラとヒットが動く。
- KO/結果：一時的にグラフィックが大きくなり、終われば選択を落ち着いてできる。
- 探索：プレイヤーの視線とNPC/地形を優先、環境UIは必要な時だけ現れる。
- キャラクリ：モデル操作中は工具の表示が退き、設定中は工具に集中。

## 04-6 3Dと2Dの層
| 層 | 役割 | 描画候補 |
|---|---|---|
| L0 | 3D世界/対戦ステージ/光/キャラ | Three.js |
| L1 | 戦闘進行とゲーム内エフェクト | Three.js / 既存シーン |
| L2 | HP/Drive/奥義・固定入力・メニュー | HTML/CSS/JS |
| L3 | 重要な一瞬の勝敗/選択演出・場面転換 | CSS/JS + Three.js連携 |
| L4 | 設定・Pause・技表・ヘルプ | DOMの独立レイヤー（入力停止） |
「UIが重なっているから困る」問題は、単なるz-indexの修正ではなく、**その場面でどの層を見せるべきか**で解決する。極端な透明化で読めなくなる解決は禁止。

## 04-7 グラフィックの持ち物
- ロゴ/紋章：意味がある場所だけ。全ボタンの角に無意味な拳印を貼らない。
- 背景パターン：キャラ/文字の背後は静か。VS/勝利だけ意図的に強くしてよい。
- 顔画像：既存9体の実モデルと一致。生成物で顔・耳・尾・装飾を変えない。
- キャラクリ：色・形のプレビューが他の装飾に埋もれないこと。
- ピクト：名前を読む前に用途がわかる記号を目指す。既存の他社UIを模写しない。

## 04-8 余白・サイズの検証
- 主CTA：まず44×44 CSSpx以上を検討、デザインは48以上を優先。文字に必要な領域と指の実寸を別々に測る。
- 主操作6個：最長「ギュイーン」が短横で折れても意味が失われないアイコン併用や別の文字配置を比較。
- 画像欠落/長い名前/日本語のフォントが読み込めない/外国語の長さによる欠落も検証。
- ガイド文の削除で説明不能になった場合は、短い初回ガイド・ヘルプ・実演で補完する。
- 正式の色値・影・線幅・フォントは採用案を選んだ後にFigma変数とCSS tokenに一対一で確定。
