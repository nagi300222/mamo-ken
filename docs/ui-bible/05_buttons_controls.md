# 05｜ボタン・スティック・入力：ひとつずつ決める

**最重要**：UIが美しくても、指で押せず、対戦開始に反応せず、戻ると保存が壊れるなら不採用。既存の入力機能は保護し、見た目とタッチ領域の改善から始める。

## 05-1 部品ごとの選択肢
| ID | 候補 | 見た目 | 強み | 注意 |
|---|---|---|---|---|
| BTN-A | 拳祭の演出プレート | 面の押し込み・強い縦縁・短い色変化 | 押した気持ちよさ・格ゲーらしさ | 何でも派手になると疲れる |
| BTN-B | 競技の高コントラスト型 | 形の整った短い矩形、瞬間的なハイライト | 視認と入力の安定性 | 汎用Webボタンに見えない造形 |
| BTN-C | 工房の触れる部品 | 紙/木/布の素材、立体的な押下 | キャラクリ・探索への愛着 | 試合中の視認性と対戦の速度 |
Figma 実試作：[操作部品ラボ](https://www.figma.com/design/afaB1eVmV6uOnDZR40t0Kr?node-id=2-2) に各タイプの Default/Pressed/Disabled、HP/Resourceの編集可能な部品を置く。まだ最終のゲーム素材ではない。

## 05-2 どのボタンにも必要な7状態
| 状態 | 画面の表示 | 入力とSE |
|---|---|---|
| Idle | 通常の触れる面。押せるか明瞭 | 無音 |
| Focus | キーボード/コントローラーの選択状態を外縁または明暗で提示 | 移動中の短い選択音（過多を避ける） |
| Pressed | 押し込み・反転・短い光。指の下でも状態が分かる | 反応は即時、必ず1回だけ発火 |
| Disabled | 理由が分からない灰色化は禁止。形と状態補助で不可が分かる | 原則確認SEを鳴らさず、必要な時だけ不足SE |
| Loading | 読込/処理中の二重押し防止 | 保存/開始は結果と区別 |
| Success | 成功を視覚/音で伝えるが操作を閉塞しない | 0/1回の肯定音 |
| Error | なぜできないか短く示し、再試行/戻りがある | 専用短音＋説明が存在 |

## 05-3 BTN-PRIMARY｜主決定ボタン
配置場面：対戦開始、決定、再戦、保存、次の相手。
- 主役のアクションは1画面で1つを原則。状況によりモード選択では選択カードそのものが決定面になってもよい。
- 文字候補：対戦開始／このキャラで戦う／決定。既存ゲーム文脈と整合しない冗長な「始めるためにここをタップ」は禁止。
- 推奨サイズ候補：高さ48〜56px、長さは日本語を詰めず最低130px（画面で実測）。操作面は44px相当以上。
- 形：Aは斜めの帯/短い打撃、Bは安定した矩形、Cは触れる札/木。攻撃ボタンと同一形状にはしない。
- キーボード/コントローラーで確定可能。ロード中の連打を守る。
- 押下と実際の開始が別時刻なら「押したことが伝わる」ことと「まだ読込中」を明確に分ける。

## 05-4 BTN-BACK｜戻る
- 戻るは常に同じ意味：前の画面/状態へ戻る。キャラ選択へ戻るなど行先指定が必要な場面はラベルを明示。
- 試合中はPauseを経由し、勝負を放棄する誤押しを防ぐ。
- モーダルを閉じた時は背景の選択状態へフォーカス/スクロール位置を戻す。
- 候補 BACK-01 左端の戻るアイコン＋短い名前、BACK-02 下部の固定小さな操作、BACK-03 コントローラーの戻る導線と画面内アイコン。
- A/B/Cすべて見た目は違っても戻る結果は同じ。押下音は決定音より軽い。

## 05-5 BTN-SETTINGS｜対戦設定・全体設定
- 「CPUやさしい・対戦相手・モード」のセレクトをキャラ選択画面に常時並べない。
- SET-01 専用設定ボタン→中央シート、SET-02 右サイドパネル、SET-03 世界観の小道具パネルを比較。
- シートの中では意味の近い項目をグループ化：対戦/操作/画面/音。CPU/相手選択の「今何が選択されているか」は必要なら要約のみ選択画面に残す。
- 開いた/閉じた時の明暗差、背景入力解除、スクロール/フォーカス閉じ込め、タッチ外閉じの誤操作を確認。

## 05-6 BTN-MODE｜5モードの選択対象
- 項目は「通常対戦」「プラクティス」「アーケード」「サバイバル」「キャラクリ＋探索」を保持。
- モードの名前を何重にも表記しない。**絵・位置・動きが分かれば説明文を削る**。
- MENU-A 舞台旗／MENU-B 大きな背景＋横タブ／MENU-C 地図の地点。いずれも5つが初見で発見できる。
- フォーカスの移動方向、開始の入れ替わり、戻る行動を統一する。

## 05-7 BTN-ROSTER｜9キャラの選択対象
- キャラ画像・名前・選択状態・無効状態・選び直しのルール。
- SEL-A 3×3顔札。SEL-B 9個横帯。SEL-C 仲間の記録片。
- 各キャラの名前をカード外で重ねて何度も表示しない。**全名は大きな選択中パネル**、一覧は顔/必要時の識別名。読上げや画像欠落時は全名を出す。
- 選択対象と「開始」は別の操作。選んだだけで開始しないか、二段階を避ける即決型かを作品全体で決める（SE・誤タップテスト必須）。

## 05-8 BTN-PAUSE｜一時停止
- 試合中に押せる/演出中はどうするか、ゲーム状態で判定。画面外ヘッダーの常時大きな「一時停止」リンクは前提にしない。
- Pauseを開く時、入力とCPU/タイマーの停止契約をゲーム本体に問い合わせる。
- UIはフェードだけで入力が残らないようにする。OSバックグラウンド復帰とは別。
- 終了/再開/設定/キャラ選択の階層・優先アクションを定める。

## 05-9 BTN-SKIP｜VS/奥義/勝利のスキップ
- スキップ可能状態でのみ表示。可視のまま押せない「飾りボタン」にしない。
- 演出がすでに終わった場合も二重進行しない。開始前のGLB読込を飛ばして戦闘が壊れないこと。
- 初回視聴時の存在は目立ちすぎず、再戦では素早く進める配置。
- 長押し必要にするか、単発押下にするかはSKIP-01/02で比較し、反応速度と誤操作の実測で決定。

## 05-10 BTN-MUTE / SOUND｜音
- 状態はON/OFFの二つ（必要ならBGMとSE別）。**単にスピーカーマークが変わるだけで状態が不明にならない**。
- 音OFF時にMute確認音を出さない。音ON再開で予告なく大音量を鳴らさない。
- メニュー・選択・バトル・Storyに設定を共有。
- モード選択時は単独ボタンか、設定内へ集約か比較。状況によって音OFFがすぐ必要な人もいるため、一律に隠さない。

## 05-11 BTN-ATTACK-6｜既存6ボタン
| 操作ID | 主ラベル | 結果の約束 | 最小の見分け方 | やってはいけないこと |
|---|---|---|---|---|
| ACT-W | 弱 | 弱攻撃 | 明確な主名・独立形状 | 固有技名の多段表示で主名を読めなくする |
| ACT-H | 強 | 強攻撃 | 弱との大小/重みの差 | 一目で弱と同じ見た目 |
| ACT-T | 掴み | 掴み/投げ | 掴む記号・別の面 | ガード/攻撃と混同 |
| ACT-G | ギュイーン | 固有の既存能力 | 形と短い主名／別の要約 | 「ギュイ／ーン」の不自然な分割で読めない |
| ACT-S | 必殺 | 方向等と組合せた必殺 | 弾/閃き、方向ガイドは別 | 現行入力契約を勝手に変更 |
| ACT-U | 奥義 | 奥義発動条件に沿う | 重い見た目＋ゲージ連動 | 演出のため攻撃入力を誤発火 |

**共通3候補**：
- ACT-A 2×3の機械的でなく弧を描く手の到達円。親指の自然な動きと衝突を測る。
- ACT-B 3×2の形/大きさの違う競技パッド。位置を覚えやすく、一目で状態が読める。
- ACT-C 4つの通常操作＋2つの大技を別材質に分ける。世界観を感じさせるが、操作位置は実測必須。
どの案も6個は維持。見た目だけの変更で判定範囲がズレないよう、**表示面とhit targetを別に定義**する。

## 05-12 BTN-MOVE / スティック
- 左スティックは滑り始めた位置、deadzone、pointerIDの管理を維持。
- 移動・後ろガード・ジャンプの方向入力は一体として扱う。
- VIS-JOY-A 透明な円の可視ガイド（ホーム画面では隠す）、VIS-JOY-B 外周だけの薄いタッチパッド、VIS-JOY-C 基本は透明でタッチ時に半径を見せる。
- 画面に重ねる時は**キャラの当たり合いの場所を隠さない**。アルファ値だけ小さくすると見えにくくなるため、輪郭/押下位置を工夫。
- 初めての人にスティックを見つけさせる必要がある。ボタンを消しすぎた結果、方向入力が分からないなら不採用。

## 05-13 BTN-STEP｜前・後ステップ
- 左スティック付近に前後専用2ボタンを維持。前後は相手との位置関係に沿う意味で、画面固定の左右と混同しない。
- DSH-A 左スティック下に小さな2連、DSH-B 横に大型2連、DSH-C スティック枠一体化を比較。
- それぞれボタン名・矢印・結果が移動方向と一致し、対戦中の誤押し/スティック干渉がないこと。

## 05-14 BTN-CREATOR｜キャラクリ
| UI | 必要な状態 | 注意 |
|---|---|---|
| パーツ選択：頭/耳/手/足/尾/装飾 | 選択中/未対応/交換候補/試着 | 外見の変化をプレビューで即見せ、元のパーツへ戻れる |
| 毛色 | 選択済み色・自作色・適用部位 | 色覚に依存しない部位名、毛模様との関係を明示 |
| 毛模様 | 4種など実機能が扱う範囲 | 型の勝手な削除禁止 |
| 戦闘スタイル | 現在の動作と技への影響 | ただの説明ラベルにせず試し撃ち案を検討 |
| 技3枠 | 使用可能/互換なし/選択中 | 実測していない異骨格技を有効にしない |
| 名前入力 | 既存・仮入力・長名・禁止文字 | IME/保存・復元・切れの検証 |
| 保存 | 未保存/処理中/完了/失敗 | 既存データを無断変換・削除しない |
| 元に戻す | 操作履歴が必要 | 履歴が実装されるまで使えるふりをしない |

## 05-15 BTN-STORY｜探索と会話
- 左スティック移動、右ドラッグ視点、NPC近接で会話、視点リセット。
- TST-A NPCへ近づくと話すボタンが出る、TST-B 視点中央のコンテクスト行動、TST-C NPCの上に表示した行動の目印。
- 会話中はボタンを**会話送り・取消・挑戦**へ再編成し、戦闘攻撃ボタンの視覚ゴミを残さない。
- Story→Battleは道場と同じ攻撃配置とHUD契約。Storyへ戻ったらカメラ/位置を復元。

## 05-16 ボタンごとに最後に記録する欄
ID｜採用候補｜用途｜表示文言｜表示位置｜描画形状｜最小サイズ｜実際のタップ領域｜状態7種｜キー/パッド操作｜短音｜演出時間｜無効理由｜画面遷移｜模擬safe area結果｜実iPhone結果｜決定者｜決定日｜却下案と理由。

この記録がない部品を、見た目だけ採用して「完成」としない。
