# 19｜実戦UIの配置と実装仕様

対象は [Issue #229](https://github.com/nagi300222/mamo-ken/issues/229)。実装ベースは [Draft PR #225](https://github.com/nagi300222/mamo-ken/pull/225)。比較案の経緯は [PR #228](https://github.com/nagi300222/mamo-ken/pull/228)。

- 右側の中心に S（必殺）、左縦に A（強）と B（弱）、上に同系の湾曲した Y（掴み）と X（奥義）、S の下に丸端の弧 Z（ギュイーン）。画面に合わせて群を縮める。各 SVG の外側に最低 44×44 CSS px の独立した HTML ボタン領域を確保する。
- 通常・押下・資源待ち・READY は不透明な色面と輪郭で区別する。サモンズボードのマットな面と厚い輪郭、ロード・トゥ・ドラゴンの画面内情報の少なさを参照した。画面の記号と物理キーの対応は技表に載せる。対戦中のボタンは記号のみ。
- HP、奥義、Drive の順。HP は連続、残る二本は十等分して端数をそのまま描画する。左右外端には既存顔素材から目の部分を切り出して表示する。満タン時は奥義バーの内側端に炎、X に色と輪郭の変化を出し、モーション軽減時も静止した形で残す。
- 操作は既存の data-control と入力経路を共有する。押せるタイミングは既存の戦闘ルールが決める。Z / X の使用不可表示も戦闘の資源・状態を参照する。技表と音・演出設定を開いた時は入力と捕捉中のポインターを解除する。
- 通常フレーミングは、左右入力領域の間を両者の投影範囲にする。中央への追従をなめらかにして、急な離隔時は画面内に収める拡張を優先する。飛び道具は両者の外側で余白を広げる補助に使う。表示だけを計算し、KO や奥義の専用カメラは既存の経路を使用する。
- 色、寸法と端末上の操作感は今回の実装値。物理 iPhone と本人試遊の判定は未実施。

素材制作は [Claude の制作セッション](https://claude.ai/chat/a78f8b49-0bc3-4ec8-9638-b7a02a61afa1) の 844×390 原案。X と Y は回転角が異なる同系の豆形で、外接矩形の寸法が異なる。実装では記号サイズ、44 px の操作領域、待機色の判読性を調整した。押下では既存の戦闘音を使う。
