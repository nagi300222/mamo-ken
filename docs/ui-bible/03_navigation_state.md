# 03｜ナビゲーション・状態遷移・プレイヤーの時間

## 設計単位
「画面」を1枚の静止画とみなさず、**入る→理解する→選ぶ→反応を得る→移る→戻る**という体験の連続として扱う。静止の美術だけを採用して、遷移で旧UIに戻る状態を認めない。

## NAV-0 共通の機能規則
| 契約 | 必要な振る舞い |
|---|---|
| 戻る | 原則ひとつ前の選択とスクロール位置、選択中キャラ、設定を保持。名前が似た「キャラ選択へ」と「前の画面へ」を混同しない |
| 確定 | 一度の押下で一度だけ遷移。二重タップ・押し続けで画面多重起動を防止 |
| 読込 | ロード中/再試行/失敗/戻るの状態を区別。見た目の読み込み演出を無限ループにしない |
| スキップ | VS、勝利映像、奥義の既存契約と整合。演出は飛ばせてもダメージ/KOの適用は1回のみ |
| 音 | 初回操作前は鳴らさず、ユーザーが音OFFなら全画面で保持。背景復帰では意図しない音を出さない |
| フォーカス | キーボード/コントローラーの選択状態を消失させない。モーダルを閉じたら元の操作へ戻る |
| 保存 | 変更前の記録を壊さず、成功・失敗・未保存が画面で区別できる |
| 入力解除 | pointercancel・アプリ非表示・回転・pauseでスティック/攻撃の保持を解放 |
| 時間 | 対戦中に演出のため判定時計を勝手に止めない。現行の奥義ムービーの停止契約のみ守る |

## NAV-1 操作の流れ
1. 起動→タイトル／メニュー→5モードのいずれか。
2. 対戦系→キャラ選択→必要時対戦設定→VS→イントロ→FIGHT→KO/TIMEUP→勝利/敗北→結果→次の対戦またはメニュー。
3. プラクティス→キャラ選択→練習→設定変更・技確認→続行→戻る。
4. Arcade→キャラ→台詞/VS→ラウンド→マッチ勝敗→次の対戦・CONTINUE・クリア。
5. Survival→キャラ→戦闘→HP持越し→次戦→敗北/終了→記録。
6. キャラクリ＋探索→作る→未保存/保存→探索→NPCへ近づく→会話→挑戦→VS→FIGHT→結果→元位置と向きに復帰→保存/再編集。

## NAV-2 メニュー遷移の候補
| ID | 形式 | 使い勝手と注意 |
|---|---|---|
| NAV-A | 演出付きステージ切り替え | キャラ・世界を強く見せるが、再選択まで待たせない |
| NAV-B | モード横スイッチ/即決 | 最短操作、競技系。5種がすべて選択可能と分かる |
| NAV-C | 地図の場所へ移動 | 世界とつながる。ボタン入力とタッチで到達回数が増えすぎない |

## NAV-3 モーダルと設定
3案とも**設定を常時載せないが、存在を隠しすぎない**。
- SET-A：中心の短いシート（現在のキャラ/試合を背景として維持）。短横画面では4項目以上を並べない。
- SET-B：右から出るパネル（選択したキャラと設定を同時に確認）。狭い端末ではフル画面の方が読みやすい場合あり。
- SET-C：紙札/道具を開く（世界観強い）。見映えに反して入力順が増えない条件でのみ採用。
共通：開く→背景入力を止める→操作可能な第一項目へフォーカス→変更→閉じる→元のフォーカスへ。端から外へ飛び出さない。タッチ・キーボード・Gamepadで確認。

## NAV-4 決定の確認段階
- 選択：取り消せるため確認ダイアログは不要（キャラ選択・モード選択）。
- 危険操作：未保存編集を捨てる、セーブを上書き/削除する → 変更内容と戻る方法を示す確認。
- 対戦開始：ロード後に操作可能。開始ボタンは入力が受け付けられた瞬間に明確な状態となる。
- 保存完了：画面が消えただけで成功扱いにしない。戻す/再編集の導線を確保。
- Pauseから終了：戦闘進行/Storyへの戻り/保存を混同しない。

## NAV-5 1.0 秒前後の時間の扱い（暫定・実装値ではない）
| 反応 | 候補値 | 備考 |
|---|---:|---|
| タップ反応開始 | 0〜50msを目標 | 実機イベント/描画遅延を別途測る |
| フォーカスの光/拡大 | 90〜140ms | 選択を連続移動する場合は後続入力を受け付ける |
| 決定アクションの予備動作 | 120〜240ms | 選ぶ喜びと速さのバランス |
| VSへの大きい切り替え | 250〜500ms | キャラ素材読込が別に必要ならロード表示 |
| 戻るの反応 | 0〜180ms | プレイヤーは待機を強制されない |
| 保存の成功表示 | 600〜1200ms程度残す | 「表示を長く残すこと」と「保存処理の所要時間」は別 |
これらは設計の**候補**。桜井氏や商業ゲームの公式数値ではない。音/タッチ/負荷で調整する。

## NAV-6 画面状態マトリクス
| 状態 | 攻撃UI | HP | スキップ | Pause | メニュー戻り |
|---|---|---|---|---|---|
| キャラ選択 | 非表示 | 非表示 | 不要 | 不要 | 戻る |
| VS/Intro | 非活動かつ非表示 | 原則非表示 | 読込完了後有効 | 契約による | スキップ/戻るルールを明記 |
| FIGHT | 有効 | 有効 | 不要 | 有効 | Pause経由 |
| ULTIMATE cinematic | 非活動・非表示 | 動画文脈優先 | 有効 | 既存停止契約 | 既存契約 |
| KO slow | 非活動・非表示 | 原則不要 | 状態に応じ有効 | 契約による | 段階に応じる |
| RESULT | 非表示 | 原則不要 | 不要 | 不要 | 再戦/選択 |
| Story dialogue | 非表示 | 不要 | 会話送り | 会話閉じる | 探索へ |
| Creator save | 非表示 | 不要 | 不要 | 入力を重複禁止 | 保存終了後 |
この表は候補。既存状態遷移が保存・CPU・KOを守ることを実証して確定する。

## NAV-7 長押し・連打・誤入力
- 選択画面：高速入力で最後の選択が決定対象となる。アニメ終端まで入力を捨てない。
- タッチ：押下した指IDを追跡し、ドラッグ/離し/キャンセルの位置と結果を紐付ける。
- 戦闘：方向＋必殺など現行入力コントラクトを優先、UI側の装飾/音で技発動タイミングを変更しない。
- Story：カメラドラッグと移動スティックを別PointerIdで管理、同時操作時に会話ボタンの入力に漏れない。
- 実機：誤押しの実測に基づいてボタン位置とタッチ領域を変更。見映えだけで配置を固定しない。

## NAV-8 導線レビューの撮影条件
モード選択→キャラ選択→VS→Fight→KO→Result→再戦を**1本の音付き通し動画**にする。Creator→保存→探索→会話→Battle→同じ位置へ帰還も別の音付き動画で確認。静止画で「体験が繋がる」と断定しない。
