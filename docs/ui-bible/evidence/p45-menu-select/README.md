# P4.5｜モード選択B・キャラ選択Aの実画面試作

作成：Claude（ヨル）、2026-11-28。ナギの指示「試遊の前にそっちを進めて」による。UIバイブル第13章で本人が選んだ方向（全体B／モード選択B／キャラ選択A）を、実ゲームの画面に組んだ試作。**配色・文字・動き・音はUIバイブル04章の候補値で、本人の採用ではない。**

## モード選択B（大ステージ＋下部5切替）

- 画面全体が選択中モードのシーン（v18の既存5枚、1280×480）。左に短い見出し・一文・開始ボタン1つ。
- 下の5つの切替を押すと、まずステージが切り替わる。開始ボタン（または表示中の切替をもう一度押す）で入る。左右キー、ステージ上の左右スワイプでも切替。
- 戻ってきたとき、URLの `#arcade` などで直前のモードを表示（ブラウザの戻る操作）。保存データには書き込まない。
- 720×320でも5つの切替・見出し・開始ボタンがスクロールなしで全部見える。縦持ちブラウザでは従来どおり横表示に回転。
- 旧カード版にあったモードごとの補足文・番号・矢印・下部の注記は外した。

## キャラ選択A（3×3＋登場）

- 左に9体の顔を3×3。右の舞台に選んだマーモットの全身（`assets/roster3d`）が足元の光と一緒に登場し、大きな名前・タイプ・得意/苦手。
- 対戦相手・モード・CPUの3つのプルダウンは「対戦設定」1つにまとめ、開くと設定シート。ボタンには今の設定の要約（例：相手 ゴダン · やさしい／CPU Lv1）。
- 選択中は上部の共通ヘッダー（技表・音・一時停止・キャラ選択）を隠す（UIバイブル02-13「SELECT：ヘッダー不要」）。
- 既存の要素（ボタン・プルダウン・開始）はidごと移動しただけで、作り直していない。対戦開始・アーケード・サバイバル・練習の処理は変更なし。
- 長い名前（ダークモグゾー）は省略せず2行で表示。

## ついでに直したもの

- `run-ui.js`：開発用の「演出確認（相手停止・奥義満タン）」が `?check=1` なしでも表示されていた既存の不具合。`?check=1` のときだけ出すよう main.js と条件を揃えた。

## 検証

- 実ブラウザ：P4 UI（MENU-B・SELECT-A・5モードの行き先・44pxタップ・保存不変）、P4 polish 2,347項目、run-modes（アーケード8戦・サバイバル・縦持ち練習）、v15.1演出、v15練習、P3フィードバック、通常技54本、native同梱（ノッチ・5モード・練習）がPASS。
- 単体：Dojo 220、共通UI・Story 31。
- 既存検査のうち、常時見えていたプルダウンを直接操作していた7ファイルは、設定シートを開いてから操作する共通ヘルパー `acceptance/match-settings.mjs` に置き換えた。
- `matte-battle-browser.mjs` のガード値検査は手元のSwiftShaderで失敗するが、選択画面の変更を外しても同じ値で失敗するため無関係（GitHub CIでは通過実績あり）。
