# マモ拳（仮） 実装指示書 v1.1（Claude Code向け）

## 0. 体制と運用ルール（凍結）

- ナギ = プロダクトオーナー / Claude = Hub（設計・仕様裁定・レビュー）/ Codex = 実装。
- 仕様の疑義・変更提案は**実装せずに質問として報告**。勝手な仕様追加・変更は禁止。
- リポジトリ: `nagi300222/mamo-ken`（新規・private推奨）。
- ワークフロー: **main直push禁止 / branch → Draft PR → レビュー → squash merge / 1PR=1目的**。
- PR本文テンプレ: 目的 / 変更点 / テスト（コマンドと結果）/ 動作確認手順 / スクショorGIF / 「仕様逸脱なし」宣言。
- 各PRは `npm run test` と `npm run build` グリーン必須。

## 1. 技術スタック（固定）

- **Vite + TypeScript(strict) + Canvas 2D（1キャンバス方式）**。描画/ゲームフレームワークの追加禁止（承認制）。
- テスト: Vitest / Lint: ESLint + Prettier。
- PWA化はPR-9（vite-plugin-pwa は承認済み扱い）。
- **外部通信コード禁止**。依存追加はPRで理由明記のうえ承認待ち。

## 2. アーキテクチャ原則（凍結）

```
src/core    … DOM/Canvas/Audio非依存の純ロジック。step(state, commands[]): BattleState
src/input   … Touch/Mouse → InputCommand 変換のみ
src/render  … stateを読んで描画のみ（状態変更禁止）
src/audio   … イベントキュー購読でSE/BGM再生
src/ai      … CPUのInputCommand生成（別seedのPRNG）
src/scenes  … title / select / battle / result 遷移
src/data    … balance.ts / characters.ts（数値の一元管理）
```
- core内 `Math.random` / `Date` 禁止。PRNGは mulberry32 を state.seed で運用。
- 決定論テスト: 同seed+同入力列 → 最終stateハッシュ一致（CIで担保）。

## 3. プロトタイプの位置づけ

同梱の `mamoken_prototype_v01.html`（単一HTML・バニラJS）は**仕様の動くリファレンス**。
- 手触り・演出・数値の初期基準として参照してよい。ロジックの読み替え移植は可。
- ただし本実装は**そのまま貼らず**、上記アーキテクチャ（型付きcore + テスト）で作り直すこと。
- プロトタイプと仕様書が食い違う場合は**仕様書（02/03）が正**、疑義はHubへ。
