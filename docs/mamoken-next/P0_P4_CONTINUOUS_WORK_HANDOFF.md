## 3. 枝とPR（提案ルール）

- 作業ベース：PR #209 の更新された HEAD SHA を明記。P0/P1、P3技、P3アート、P4デザイン、P4 UI実装、P2互換は**独立したDraft PR**。
- 可能な限りファイル所有権を分離。戦闘共通入力とstory/main.jsのP0変更をP4が無断上書きしない。
- 大型GLB編集はPRに元データSHA・生成器/Blenderソース・テスト動画、性能値は端末環境を添える。画像だけを「動作済み」としない。
- 統合Draftが同じbase PRを指すようにし、mainは統合しない。マージは本人の別途明示GOが必要。
- 各PRの受入結果に未実機/未CI/未映像の欄を設ける。表示FPS・CPU勝率・レンダラー種別を混同しない。

- **試遊合格**：実iPhoneにおけるナギ自身の使いやすさ/面白さ判断（端末の機能検証も含む）。
