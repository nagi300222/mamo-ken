# マモ拳 P3｜戦闘の手応え・全9体の技モーションディレクション v0.1

> 2026-11-23 / ミオの制作設計案（本人の技性能最終決定ではない）。**このPRは設計資料であり、GLB/ゲーム実装済みの主張ではない。** 実制作の担当はClaude、戦闘シミュレーションと技判定はCodex、統括Work。実装基準は [PR #209](https://github.com/nagi300222/mamo-ken/pull/209)。[P3 Issue #212](https://github.com/nagi300222/mamo-ken/issues/212)。

## 0. この設計で作りたいもの

「**キャラが動き出した瞬間に個性がわかり、技が当たった理由と外れた理由がわかる**」こと。派手なエフェクトは技の実動作の代用品にしない。

- **参考する設計原理**：スマブラの「方向＋必殺ボタンで少数操作から多様な技」、スト6の「見やすいリソースと簡略入力による入りやすさ」、桜井政博氏の公開ゲーム制作動画にある「ヒットストップ」「操作の重さ」「遅さは罪」の観点。コピーではなくマモ拳への適用案。
- 対戦の基本：弱/強/掴み/ギュイーン/方向＋必殺/奥義、従来の通常技6本×9体、必殺3本×9体、固有能力1体につき1つ。**元の9奥義約10秒、命中後だけ映画へ、空振り・ガードで映画なし**。
- この資料の命名・アクションの解釈は**演技の方向性**。P3で既存技の種類・データと一致しない提案は、必ず差分として本人に提示。キャラの背景設定を創作して正本化しない。全員マーモット。

## 1. 9体のプレイフィール定義

| キャラ（ID） | 初見で伝えたいこと | 弱点も含む設計 |
|---|---|---|
| モグゾー (`moguzo`) | 万能・初めてでも触れるが、根性による逆転で深みを作る | 突出した距離・高速連打は持たない |
| ピスケ (`pisuke`) | 最速級の移動と機敏な蹴り | 相手の空振りを見て入る。体力/ガード耐久で弱み |
| ゴダン (`godan`) | 重量・間合いを詰めて大打撃 | 強さは予備の大きさ/被ガードの危険と表裏一体。CPUが理不尽にならない |
| ハクマ (`hakuma`) | 防御・位置取り・掌の押し返し | 防御成功が次の攻撃に繋がるが、追い掛け性能は低い |
| チルカ (`chirka`) | 視線誘導と遅延/フェイント | 偽の動きと本当の打点を判別可能に保つ |
| タキマル (`takimaru`) | 近接・投げのプレッシャー | 近付くまでが難しく、掴み択の予兆は見える |
| ヨミカゲ (`yomikage`) | 待ちと反撃 | 読み勝ちの快感、空振りのリスク、当て身成立の納得感を重視 |
| バレット (`bullet`) | 長尾の距離支配と装填 | 尾の長さを不自然な透明判定にせず、本当の先端を使う |
| ダークモグゾー (`dark_moguzo`) | 低耐久の高速連係 | リスクを取って展開を続ける。モグゾーの色違いではなく独立した動き |

### 運動の差別化と表情
- 待機には**体重の置き方**の違いを付ける。モグゾーは中心軸、ピスケはつま先で軽く、ゴダンは沈み、ハクマは安定、チルカは予備の揺れ、タキマルは手を開く、ヨミカゲは静止、バレットは尾を支点、ダークモグゾーは前傾。
- 歩き/前後ステップ/ジャンプ/着地/ガード/被弾/KO/勝利は同じキャラ固有リズムでまとめる。小さなモーション差だけで「別キャラ」と言わない。
- シルエット→接触姿勢→戻り→SE→VFX→数値の順でレビュー。演出だけを変更して実判定を置き去りにしない。

## 4. 手応え＝判断の連鎖

| 場面 | 見えるべき理由 | 音と映像のレイヤー | 実装側の確認 |
|---|---|---|---|
| 弱がヒット | 当たった手/足とヒット点が一致 | 短い接触音＋小さな止まり | active姿勢とhitbox、cancel可能時間 |
| 強がヒット | 予備で大きさを知らせる | 低音の接触音＋打撃面の強調 | 威力・硬直・ガード時の反撃可能性 |
| 空振り | 間合いを読み違えたとわかる | 接触音を鳴らさず空気を切る音だけ | 回復まで行動制限が説明可能 |
| ガード | 当たったが防がれた | 鈍い防御音＋小さな画面反応 | ガード硬直・削り・ゲージの整合 |
| 対空 | 上に向かう形が明瞭 | 上向き軌跡＋踏切り音 | 空中被弾/接触/着地 |
| 掴み | 手が届く・拘束が成立 | 一瞬の重い「組み」の音、ペア演技 | 体格別接触、投げ成立条件 |
| ギュイーン | 強引に押す特別な行動 | 突進音とクラッシュ、装甲がわかる反応 | Driveと解除条件 |
| 咆哮 | 方向↓+必殺の対抗手段 | 低音から放つ一声、攻撃/弾相殺と一致 | Drive35・割込・ヒット判定 |
| 奥義命中 | 勝負の転換点 | **命中確定後に**専用10秒映画 | タイマー/CPU/Battle凍結/スキップ/KO遅延 |

- **提案**：低い打撃で少ないヒットストップ、重い打撃で長めのヒットストップという方向で検証。ただし具体的F数は元の仕様と実際の気持ちよさの比較で決める。全キャラ同じ停止時間へ一括上書きしない。
- 戦闘中の表示文は「プレイヤーに必要な事実だけ」。ダークモグゾーの不要な『闇の力が高まってきた』はP0修正の範囲。固有能力や駆け引きを曖昧にするテキストは廃止。
- SEを足してもスマホの小さなスピーカーでつぶれないか、iPhone実機で確認。BGMと効果音は別音量。

## 5. Codexへ渡す数値・検証データの形式

**現状を先に抜き出すこと**：各技の startup / active / recovery / damage / reach / vertical contact / travel / cancel window / blockstun/hitstun / CPU使用率 / モデル名 / モーション名。ソース `exp/fable-3d/dojo/balance.js`, `normal-balance-v151.js`, `normal-contacts-v151.js`, `fighter-style.js`, `cpu.js`, `models.js`。提案値は別列にして現状と混ぜない。

1. 現行バランスを凍結した比較ベース。9×9 CPU戦は左右入替・難易度別・seed固定。CPU勝率は対人バランスの代替ではない。
2. 「見えたのに当たらない」「当たったように見えないのに判定がある」を最優先の不具合として修正する。
3. 画面横長での輪郭の区別、手足が床を貫通/骨折しない、左右反転、ジャンプ/屈み/被弾割込、ギュイーン/奥義から復帰。
4. **既存v15.1の実スキン面と判定の1.5cm以内の整合確認**を参考ゲートに使う。ただし新しい技では新たに実測し、姿勢と当たり方が納得できることを加える。
5. 必殺3枠のカスタム技参照(`MoveRef`)を壊さず、P2で互換範囲が広がる場合にデータ更新可能にする。
6. 素材PRとルールPRを別Draftにし、映像/フレーム表/実検証を添える。移植済みとは言わない。
