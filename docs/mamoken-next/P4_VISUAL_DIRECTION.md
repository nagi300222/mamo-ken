# マモ拳 P4｜全モードUI・アートディレクション v0.1

> 2026-11-23 / ミオの初期制作案。**ナギの採用確定ではない。アート素材・ゲーム画面の実装/実機検証は未完。** WorkがP0/P1実装を継続する間に本案のデザイン検討とClaudeのラフ・実制作を並行可能。 [P4 Issue #213](https://github.com/nagi300222/mamo-ken/issues/213) / [P3技モーション](P3_FIGHT_FEEL_DIRECTION.md)。

## 1. UIがプレイヤーに約束すること

- **何を選べば何が始まるか、一目でわかる**。単に5つの角丸カードを均等に並べず、遊びの種類を大きな優先順位で表す。
- **格闘ゲームは画面の中心に対戦相手**。手で隠れる場所に重要な接触点を置かない。HUDはダメージ/ゲージ/時間だけを大きく、説明は必要時のみ。
- **探索と格闘は同じ世界、異なる遊び**。探索の自由移動→対戦ボタンへの切替に違和感を作らない。Story専用の別戦闘HUDを再実装しない。
- **見せたいキャラは大きく、文字は少なく**。メニューに世界観の要素を入れるが、木目・墨・稲妻・雪を全面に足して読みにくくしない。
- **マモ拳の世界はマーモットの拳と集落**。格闘大会/武道の張り紙＋山の地形＋キャラの毛並みという固有素材を軸に、SF6のグラフィティやスマブラの選択枠を複製しない。

## 2. アートディレクション候補：山の道場 × 旅の札

これはミオの第一案。本人の世界観設定を上書きせず、既存のアセット/9キャラを活かしてまず2Dラフ2案をClaudeが提示し、色違いではなく構図ごと比較する。

- **A「山の格闘大会」**：濃い森の影 / 生成りの札 / 鈍い金 / 斜めに走る山稜線。速度を強める斜めの切り替え。大会の場内アナウンス風の押し引き。
- **B「旅人の稽古帖」**：素朴な集落の木札 / 手描きの地図 / 技を記した札 / 落ち着いた余白。探索・キャラクリに強いが、対戦UIでは引き締めが必要。
- **統合方針の仮案**：Aを対戦・モード選択、Bをキャラクリ・探索に使い、配色とナビゲーションを共通化。ゲーム内で「別アプリ」に感じさせない。

## 3. 画面情報設計（5モード）

### 3-1. モード選択
- 初期画面に大きい「対戦する」アクション。通常対戦・アーケード・サバイバルは同じ「拳を交える」カテゴリとして見せつつ、**5モードの数は維持**。
- 「自分を作る／旅に出る」は大きな横長のカード、生成した自キャラがいればその顔と名前で表示。既存のアバターデータを勝手に上書きしない。
- 「練習する」はサブアクションとしてすぐ辿れる位置。メニュー階層を深くしない。
- キャラ・モードが決まるまで画面中央の3Dアクターの見せ場を空け、余計な小見出しを減らす。
- 初回と2回目以降では説明の量を変えてよいが、毎回同じ場所から同じモードへ行けること。静止画・キーボード・画面読み上げで意味が通じること。

### 3-2. キャラクター選択
- 9名の顔/姿を大きく表示。顔画像が読み込めなくても名前と戦闘タイプを見せる。マモットと誤記しない。
- 選択しているキャラの「得意・苦手」を対にして、単なる「万能」「高速」だけで終えない。
- 選択確定時だけ小さく打撃音＋キャラ固有の構え（0.5〜1秒程度の候補）。確定前の長いアニメが操作を邪魔しないこと。
- CPUの難易度設定やモード固有の説明は別段。勝率のような未検証数値をプロフィールに載せない。
- 「決定」「戻る」は片手で誤押下しにくい位置。ボタン操作でもスキップ可能。

### 3-3. 共通Battle HUD（通常 / Practice / Arcade / Survival / Story）
- **上段**：左1PのHP + プレイヤー名 ｜ 大きな残り時間 ｜ 右CPUのHP + 名前。
- **HPの下**：Drive、奥義（充填が分かる）。ガード/固有能力は小さな専用場所。状態が変わった瞬間だけ強調。
- **中央の視界**：顔、拳の接触、弾が通る高さを覆わない。大きい演出字幕を常時出さない。
- **下左**：移動スティック＋前後ステップ。**下右**：弱/強/掴み/ギュイーン/必殺/奥義の既存6ボタン。Storyだけ別配置は禁止。
- **下段のデバッグ表示**：通常非表示。Practiceでは当てたダメージ、硬直差、連続ヒットをモード固有の控えめなパネルへ。
- **重要な瞬間**：KOは大きく、一瞬だけ。演出は勝敗や入力をブロックする場合にスキップ可能。勝利映画が初見ならそのまま、再戦では短縮を選べる。
- ラウンド制/HP持ち越し/勝抜は画面のルール情報として表示しても、入力UI自体は変えない。現在のBattleの各モード状態を共通APIで渡す。

### 3-4. キャラクリ
- **3Dプレビュー主役**。横画面で左または中央の広い領域にモデル、残りに編集コントロール。全部の項目を一画面に羅列しない。
- 編集導線：「体格・パーツ」→「色・毛模様」→「戦闘スタイル・3技」→「名前と保存」。どのタブからでもプレビュー維持。変更のたびに装飾/毛束/目鼻がつぶれないか検証。
- **パーツ互換の理由**：選べない技は「未対応」とだけ出さない。「長尾6ボーンが必要」「この手足の打撃は接触計測が未完」等、具体的な理由を説明。将来はパーツ追加か代替モーションを提示。無断の代替装備は禁止。
- **初心者配慮**：「基本スタイルにおまかせ」「おすすめの技を仮セット」「自分で詳細設定」を同じ入口に。推薦は保存前にプレビュー可能。
- 保存した名前/色/技、Story進行を壊さず再編集。体格を変えて技互換が失われても、選択を黙って消さない。

### 3-5. 探索
- 地図/道/相手の見せ場のためHUDは最小限。左移動・右ドラッグ視点・視点リセット、会話ボタン。**P0が技術正本**。
- 敵へ近づくと名前＋「話す」のみ。勝負をしたことがあるなら戦績を小さく出せる。常時ゲーム全体の説明文を表示しない。
- 会話の文字を読み進める操作、キャンセル、稽古への遷移を統一。短い相手のセリフに自由な時間を取らせない。
- 返ってきたとき、同じカメラ角度/位置/キャラで再開。P0の独立カメラでリターン座標・視点が一致するようにする。

### 3-6. VS / イントロ / KO / リザルト
- VSで顔2枚・固有色・名前を優先。顔アップは既存本物の3Dモデルを使用。ナレーション・大文字は少量。
- スキップできない導入演出を増やさない。各ムービーのロード・対戦開始・中断を一本の状態機械で扱う。
- 奥義は命中時に限り映画へ、元9体の本人指定ムービーを保護。Storyカスタム映画は未対応範囲を明示。
- リザルト：勝敗→使用キャラ→次の行動（再戦/続き/戻る）が読む順番。長文の感想でプレイヤーを引き止めない。

## 4. 画面間の一貫性契約

| 情報/操作 | 通常対戦 | Story戦闘 | 探索 | キャラクリ |
|---|---|---|---|---|
| 左スティック | 相手方向への移動/ガード | 完全共通 | カメラ基準の自由移動 | 使わずプレビュー操作に限定 |
| 右側 | 6つの攻撃ボタン | 同じ配列・同じ処理 | 右ドラッグで視点/会話 | 色・形状・技設定 |
| 戻る/中断 | pause→選択へ | pause→Storyへ | pause→モード選択 | 変更破棄の確認 |
| 体力/Drive/奥義 | 同じ3資源表示 | 同一コンポーネント | 表示しない | 能力説明とプレビューのみ |
| 対戦中に意味のないテキスト | 出さない | 出さない | 常時出さない | 説明はオンデマンド |

**キーボードとタッチ双方で検証**。右ドラッグはStory Battleへ入ると必殺入力に漏れない。pointercancel/画面回転/バックグラウンドで全入力解除。

## 5. Claude・Codexへの制作要求

Claude（アート）
- 候補A/Bの**画面構図が異なる**ラフを最低2案（モード、Battle、キャラクリ、探索）。単純な色替えではない。
- 全9キャラの顔・構えの切抜き、UIグラフィック（山稜線、拳の紋、控えめな札の質感）を著作権上問題のないオリジナルで制作。全員マーモット。
- VS→Fight→KO→勝利、キャラクリ3D操作、探索からバトルの短いUX映像。映像生成の画像だけでは動作合格としない。
- フレーム/モーション/ボタン画像・アイコンの再編集可能な原データと素材一覧。質感の使い回し・エッジ過剰・文字焼込みを避ける。

Codex（UI統合）
- まず色/余白/状態のtoken辞書、共通InputProfile、共通BattleHUD、モード選択画面・StoryのUIレイアウト統一。演出はCSS/Canvas/Three.jsから役割分担を整理。
- WebGLゲームに干渉しないようDOMを重複描画しない。動的な名前/技の長文/多言語を想定。横画面のノッチ/safe-areaと大型/小型iPhone。
- メニューボタン、6ボタン、入力バッファ、フォーカス、キーボードで通常・Story同じ動作。P1がCapacitorならCSS90度回転の二重適用は避ける。
- 現行Node/Chrome合格を保全し、実WebGLキャプチャ＋比較動画・入力/状態テストを提示。ゲーム本体の動作前に完成としない。

## 6. 合格ゲート

1. 新規UIの見た目が**マモ拳固有**で、汎用カードや角丸パネルだけではない。だが直感性を犠牲にしない。
2. 初見1分で「通常対戦・練習・8戦・サバイバル・自キャラ探索」を区別できるか。操作を間違えたら戻れるか。
3. 3秒で自分のHP/ゲージ/残り時間が読めるか（本人試遊評価）。
4. iPhone横向き・ノッチ・画面回転・片手/両手・ダークモード/色覚/音OFF/モーション軽減の表示を検証。
5. Story戦闘が道場と共通HUD+入力。指でキャラを隠さず誤押しが少ない。
6. 9体の専用映画/54通常/27必殺・Arcade/Survival/Practice・セーブの回帰。
7. **P4までの統合実装が完了したらナギのまとまった試遊を受け、その後にP5へ**。小さな未完成モックごとに本人判断を求めない。
