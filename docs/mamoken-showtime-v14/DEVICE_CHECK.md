# v14 実機確認版

通常のThree.js対戦に全27必殺の新しい演技と9奥義を統合した確認版。mainへのマージではなく、PR #180を親とする子Draft #184で管理する。Claudeの追加制作は `art/mamoken-v14-device-polish`。

## スマホでの確認

確認用URLはPR #184の本文に記載する。SafariまたはChromeで開き、横画面にする。

1. キャラと相手を選んで「対戦開始」。確認版では「演出確認（相手停止・奥義満タン）」が最初からON。
2. 右の「奥義」で実際に相手へ当てると約10秒の専用ムービーが始まる。近距離配置なので、移動せず押せば当てやすい。空振り・ガードから直接映画を開く仕組みは追加していない。
3. 自然終了と「スキップ」の両方を確認。確認モードでは対戦画面に戻った後、近距離・体力・ゲージを戻すので繰り返せる。
4. 「キャラ選択」に戻って確認モードをOFFにすれば、通常のCPU対戦も確認できる。
5. 重い場合は「音・演出」の演出をOFFにして比較。確認版の下端にはFPSと最初の読込時間を表示する。

見たい点は、操作の押しやすさ、映像が引っかかるか、音と接触が合うか、ムービー後に入力できるか、数分続けた時の発熱。問題があれば機種・ブラウザ・キャラ/相手・操作・表示FPSを一緒に記録する。OSが動きを減らす設定の場合はカメラと強い光の演出を抑える。

## 実装上の変更

- 制作用GLBの描画用の造形・画像・未使用クリップを実行時の追加ファイルから除去。追加アニメは9体合計56,426,184→32,182,992 bytes（42.97%減）。別途仕上げ2本は106,216 bytes。元モデルは変更しない。
- アニメの入力時刻・出力値・バインド先は元と同一。再サンプリングや量子化は行わない。表情トラックをGLTFLoaderが捨てないための極小三角形だけを残し、読み込み後に破棄する。小型GLBは `pack-showtime.mjs` がビルド時に生成する。
- アニメ読込Promiseを最大4ファイル共有し、同キャラ同士でも同じ追加アニメを繰り返しデコードしない。失敗時にはキャッシュを除去し、再試行できる。
- ヨミカゲの当て身成功に0.35秒の反撃専用クリップを接続。Battleの即時行動可能状態は変えず、新行動・移動・被弾で演技を中断する。
- バレットs3は骨盤・尻尾の軌道を維持して上体と四肢を刷新。奥義の確認版表示名は「尾連・爆ぜ木の実」。戦闘データの名前・性能値は別管理のまま。

## 検証の境界

単体検証、Pagesビルド、ソフトウェアWebGL、全81組の奥義、尾の全49フレーム比較、反撃の中断、連続ムービー後のGPU資源数を検証する。CIの結果はPR #184から参照する。

クラウドの画面操作ブラウザではWebGLコンテキスト作成が拒否されたため、そこでゲームの合格判定はしていない。GitHub Actionsの実Chromiumで描画・操作を確認する。実機のFPS・消費メモリ・発熱・屋外視認性の合否は、実機確認後に決める。
