# マモ拳 2Dピクセルアート・リグ方式の品質検証

モグゾー・ピスケ・ゴダンの3体を、新規のピクセルアートと骨格アニメーションで動かす実験。
ゲーム本体ではなく、キャラ素材・リグ・モーションの作り方を確かめるためのもの。
既存の `src/` `assets/` `data/` `dist/` `index.html` には触れていない。

見た目の採否はナギが判断する。この README は判断材料の置き場所と使い方をまとめたもの。

## まず見るもの

| 見たいもの | 場所 |
|---|---|
| 動いている様子 | ビューワー（下の「起動方法」）か `out/<id>/gif/*.gif` |
| 元絵との比較 | `out/compare/compare_<id>.png`、3体の並びとシルエットは `out/compare/lineup.png` |
| 全コマの一覧 | `out/<id>/contact.png`（行 = モーション。順番は `chars/<id>/manifest.json` のとおり） |
| 計測結果 | `docs/validation.md` |
| 原画の分析 | `docs/analysis.md` |

## 起動方法

依存パッケージはない。Node 18 以上と、静的ファイルを配信できるものがあればよい。

```bash
python3 -m http.server 8765
```

リポジトリ直下で上を実行し、`http://localhost:8765/experiments/pixel-rig/` を開く。
`experiments/pixel-rig/` を直下にして配信しても動くが、その場合は「元絵を並べる」だけ表示されない。

ビューワーでできること：キャラ変更、3体を並べる、モーション選択、等速〜1/10 のスロー再生、一時停止、1コマ送り、タイムラインのつまみ、骨と接地点の表示、回転中心の表示、左右反転、移動の反映の切り替え、セル枠と足元原点の表示、元絵を横に並べる。

書き出しと検証は次のとおり。

```bash
node tools/export.mjs
```

```bash
node tools/validate.mjs
```

```bash
node tools/compare.mjs
```

パーツ画像を描き直すときだけ `node tools/paint.mjs` を使う（後述の注意あり）。

## 構成

```
experiments/pixel-rig/
  index.html, viewer/        ビューワー（静的HTML + Canvas）
  src/rig.js                 リグ計算（FK / IK / 揺れ物 / 補完）と描画。ブラウザと Node の両方がこれを使う
  src/png-node.js            Node 用の PNG 読み書き
  src/gif-node.js            Node 用の GIF 書き出し
  chars/index.json           キャラ一覧
  chars/<id>/rig.json        リグ定義（関節位置・回転中心・親子・描画順・IK・揺れ物・補完・構え）
  chars/<id>/palette.json    パレット
  chars/<id>/parts/*.png     レイヤー別の透過PNG（1パーツ1ファイル）
  chars/<id>/motions/*.json  モーション（ポーズデータ）
  chars/<id>/manifest.json   そのキャラが持つモーションの一覧
  tools/paint/<id>.mjs       パーツを描くスクリプト（キャラごとに別々に書いてある）
  tools/export.mjs           全コマPNG・スプライトシート・anim.json・GIF・コンタクトシート
  tools/validate.mjs         足滑りなどの計測 → docs/validation.md
  tools/compare.mjs          元絵との比較画像
  tools/browser-check.mjs    ブラウザと Node の描画が一致するかの確認（Playwright がある環境だけ）
  out/                       書き出し結果
  docs/                      分析メモと検証結果
```

### 書き出し結果の仕様

- セルは3体共通で **224×176 px**。足元原点（`root_ground`）はセル内の **(96, 160)**。画面右向き。
- `out/<id>/frames/<モーション>_<連番>.png` が1コマずつの透過PNG。移動量は絵に含めていない（ジャンプ中も足元原点の位置に描く）。
- `out/<id>/sheet.png` は行 = モーション、列 = コマ。
- `out/<id>/anim.json` に各コマの矩形、保持フレーム数（60Hz）、そのコマでゲーム側が足す移動量 `root`、等速移動 `velocity`、接地している足 `plant` が入っている。
- GIF は確認用で、移動量を反映して3倍に拡大してある。

## ピクセルアートの作り方と、その限界

パーツ画像は **`tools/paint/<id>.mjs` に書いた図形とドットの指定から生成**している。楕円・カプセル・多角形・1px 線・文字で打ったドット絵（目、拳、足先など）を、アンチエイリアスなしでパレット色だけを使って置く。元絵の縮小・減色・トレースはしていない。元絵から取ったのは、数か所の色の中央値（パレット設計の出発点）と、目で見た形の特徴だけ。

これは「人がドットを1つずつ打った絵」ではない。輪郭や色面は意図して決めているが、手打ちのドット絵ほどの密度や味はない。この点は採否の判断材料として明記しておく。`chars/<id>/parts/*.png` は普通の PNG なので、ドット絵ツールで直接描き直せる。ただし **`tools/paint.mjs` を再実行すると上書きされる**ので、手で直したあとは実行しないこと。

- キャラの高さ：基準姿勢でモグゾー 109 px、ピスケ 112 px、ゴダン 117 px（目安の 96〜144 px の範囲内）。
- 色数：各キャラ 28 色（素材4種 × 5階調 + 目・鼻・爪などの単色8）。`palette.json` で管理し、パレット外の色がパーツに混ざると読み込み時にエラーにする。
- 毛皮はノイズで表現していない。色面、腹の明るい毛との境目ののこぎり歯、輪郭の決まった位置に置いた房、数本の刻みだけで表している。

### 陰影と輪郭線の付け方

パーツは基本色の平塗りで持ち、陰影と輪郭線は**パーツを回転・合成したあとの低解像度バッファ上で**付けている。

1. グループ（胴体、頭、近い腕…）ごとに平塗りパーツを合成する。
2. グループのシルエットに対して、後ろ下の縁を1段暗く、前上の縁を1段明るくする（パレットの階調をずらすだけ）。
3. 別のグループの上に重なる境界に、その素材の最暗色で内側線を引く。肩の付け根だけは線を引かずになじませる。
4. 最後に全体の外周へ 1px のアウトラインを付ける。

こうすると、腕を回しても影の向きが変わらず、輪郭線が回転で太ったり欠けたりしない。関節をまたいで影がつながるので、肘や膝で陰影が段になることもない。代わりに、影の形を1ドット単位で狙って置くことはできない。

### 回転でピクセルが崩れることへの方針

- 描画は 224×176 の内部バッファに行い、表示時に整数倍へ拡大する。ビューワーは `imageSmoothingEnabled = false` と `image-rendering: pixelated` を使う。
- パーツの回転角は **5.625°（360°の64分の1）刻み**に丸める。関節の位置は丸めずに計算し、絵を置くときだけ整数ピクセルに合わせる。
- 回転は最近傍サンプリング。上のとおり陰影と輪郭線は回転のあとに付けるので、崩れるのは平塗りの縁と、パーツに焼き込んだ細部（爪、拳の線、毛の刻み）だけになる。
- 回転で読めなくなる箇所は差し替え絵で対応する。いま使っているのは拳（構え用の縦向きと突き用の横向き）、目（開き・半目・閉じ・被弾）、眉、口（閉じ・開き・食いしばり）。
- 左右反転は、描き終えたバッファを足元原点で鏡像にする。装飾やレイヤー順はそのまま裏返るので破綻しない。

## リグ

`chars/<id>/rig.json` の主な項目。

| 項目 | 内容 |
|---|---|
| `bones` | 関節。`parent`（親）、`at`（親から見た位置）、`len`（長さ） |
| `spine` | `pelvis → torso → chest → neck → head` の順に回転を積む背骨 |
| `fk` | 単純な回転だけの関節（`jaw`、左右の耳） |
| `limbs` | 腕と脚の IK 定義。腕は肩・上腕・前腕・手首・拳、脚は太腿・脛・足首・足・つま先 |
| `chains` | 揺れる骨。尻尾（付け根・中間・先端）、ハチマキの垂れ2本、帯の垂れ2本 |
| `fills` | 関節の隙間を埋める補完（腰、みぞおち、首、肩、肘、股関節、膝） |
| `colliders` | 胴体が地面にめり込まないようにする円 |
| `groups` | 描画順 `z`、陰影の幅、遠い側を1段暗くする `tone`、線を引かない付け根 `merge` |
| `parts` | パーツ画像。乗る骨 `bone`、画像内の回転中心 `pivot`、グループ内の順番 `order`、差し替え枠 `slot` |
| `stance` | 構え。すべてのモーションの土台になるポーズ |
| `cell` | セルの大きさと足元原点 |

名前の付け方：カメラから遠い側（前に出す手足）が `_l`、近い側（後ろに引く手足）が `_r`。

必須機能との対応。

1. **回転中心**：パーツごとに `pivot` を持ち、骨の位置を中心に回す。
2. **足の接地**：足は「足裏の位置」をターゲットにした2ボーン IK。かかとを上げるときは母指球を支点にするので、接地点は動かない。
3. **手首・拳**：拳は前腕からの相対角度を持ち、`swap` で絵を差し替えられる。
4. **隙間の補完**：`fills` が2つの骨の間を太さの違うカプセルで埋める。画面空間で直接塗るので、どの角度でも欠けない。
5. **しゃがみで潰れない**：パーツを拡大縮小する機能そのものがない。腰を落とすと脚が IK でたたまれ、胴体が地面に届く分は `colliders` が腰を押し上げて止める。
6. **左右反転**：描画後の鏡像。
7. **JSON だけでモーション追加**：下の手順のとおり。実際に1つ追加して確かめた（モグゾーの `crouch_light`。追加時に変更したのは JSON 2ファイルだけ）。

届かないターゲットを指定しても腕や脚は伸びない。まっすぐ伸び切った位置で止まり、ビューワーと検証に警告が出る。

## モーションデータの書き方

`chars/<id>/motions/<名前>.json`。

```json
{
  "loop": false,
  "step": 3,
  "plant": ["footL", "footR"],
  "keys": [
    {"hold": 3, "pose": {"handL": [15, 3, 0]}},
    {"hold": 6, "pose": {"handL": [26.5, -2, 0], "swap": {"fist_l": "fist_l_punch"}}},
    {"hold": 6, "tween": "out", "pose": {"handL": [19, 1, 0]}},
    {"hold": 3, "pose": {}}
  ]
}
```

- `hold`：そのキーを保つフレーム数（60Hz）。
- `step`：絵を更新する間隔（60Hz フレーム）。3 なら 20fps、4 なら 15fps。
- `tween`：次のキーへ向けて補間する。`none`（既定。止め絵）、`linear`、`in`、`out`、`inout`。補間した結果も `step` ごとにしか更新しない。
- `pose`：構え（`rig.json` の `stance`）に上書きする値だけを書く。空の `{}` は構えそのもの。
- `plant`：接地している足。検証がここを見て足滑りを測る。モーション全体にもキーごとにも書ける。
- `root`：そのキーでの移動量。ジャンプの高さやダッシュの距離。
- `velocity`：歩きなど等速で進むモーションの速さ（px/フレーム）。
- `base`：そのモーションの全キーに共通で上書きする値。
- `poses`：名前付きポーズ。キーの `pose` に名前を書くか、`{"use": "名前", ...上書き}` で使う。
- `feetSpace: "world"`：足の位置を「モーション開始位置を原点にした地面座標」で書く。ダッシュのように root が動くとき、接地中の足は同じ数値を書き続ければ滑らない。

ポーズに書ける値。座標は x が前（画面右）、y が下。地面が y = 0 で、上はマイナス。角度は度で、プラスが前へ倒れる向き。

| キー | 意味 |
|---|---|
| `hip: [x, y]` | 腰の位置（足元原点から） |
| `pelvis` `torso` `chest` `neck` `head` | 背骨の各関節の角度（親からの相対） |
| `jaw` `ear_l` `ear_r` | 顎と耳の角度 |
| `shL` `shR: [x, y]` | 肩を前後上下へずらす量 |
| `handL` `handR: [x, y, 拳の角度]` | 手首の位置（肩から見た位置） |
| `footL` `footR: [x, y, 足の角度, かかと上げ角]` | 足裏の位置（足首の真下の点） |
| `bendL` `bendR` `kneeL` `kneeR` | 肘・膝の曲がる向き（1 か -1） |
| `tail` `hachiA` `hachiB` `beltA` `beltB` | 揺れる骨の目標の形（各骨の角度） |
| `swap: {"枠": "パーツ名"}` | 差し替え。枠は `fist_l` `fist_r` `eye` `brow` `mouth`。`"none"` で非表示 |
| `z: {"グループ名": 数値}` | そのキーだけ描画順を変える |

## 追加手順

### モーションを1つ追加する（実際に行った例：モグゾーのしゃがみ弱）

1. `chars/moguzo/motions/crouch_light.json` を作る。しゃがみの姿勢を `base` に置き、前手を引く→突く→戻す→しゃがみ姿勢、の4キーを書いた。しゃがんだまま終わるモーションなので `"returnsToStance": false` を付けた（検証の「構えに戻っているか」の対象から外す印）。
2. `chars/moguzo/manifest.json` の `motions` に `"crouch_light"` を足す。
3. ビューワーを再読み込みすると、モーションの一覧に出る。骨表示とコマ送りで確かめる。
4. `node tools/export.mjs moguzo` と `node tools/validate.mjs` を実行する。

このとき `src/` `tools/` `rig.json` パーツ画像には触れていない。最初は突きの位置が高すぎて前手が頭の後ろに隠れ、IK の警告も出たので、JSON の数値を直して解消した。

### パーツ（差し替え絵）を追加する

1. `tools/paint/<id>.mjs` に `part('名前', ...)` を足すか、同じ大きさの感覚で PNG を直接描いて `chars/<id>/parts/名前.png` に置く。
2. `rig.json` の `parts` に `"名前": {"bone": "乗せる骨", "group": "グループ", "slot": "差し替え枠", "pivot": [x, y]}` を足す。スクリプトで描いた場合、`pivot` と `size` は自動で書き込まれる。
3. モーションの `swap` で使う。

### 骨や揺れ物を追加する

1. `rig.json` の `bones` に骨を足す。
2. 単純に回すだけなら `fk` に名前を足す。揺らすなら `chains` に、付け根の骨と位置、骨の並び、硬さ `stiff`、減衰 `damp`、重力 `gravity` を書く。
3. その骨に乗るパーツを `parts` に足す。

### キャラを追加する

1. `chars/<新id>/` に `rig.json` `palette.json` `manifest.json` を作る（既存キャラのものを写して数値を変える）。
2. `tools/paint/<新id>.mjs` を書くか、PNG を描く。
3. `chars/index.json` に id を足す。

## 仮値として置いたもの

- **ピスケの体格比**（身長 1.03 / 幅 0.90）。資料側で未確定の初期候補をそのまま使った。
- **身長の測り方**。「背骨の角度をすべて 0 にした姿勢で、耳の先から足裏まで」と自分で定義した。構えではピスケは前傾、ゴダンは低重心なので、見た目の高さの差はこの比より小さい。
- **横から見た形**。横顔の鼻先の長さ、背中の丸み、尻尾の位置と長さ、足の長さ、手足の長さは、正面の元絵からの推定。
- **基準の大きさ**（モグゾー 109 px）とセルの大きさ（224×176、原点 (96, 160)）。
- **モーションのフレーム数、歩く速さ、ダッシュの距離、ジャンプの高さ**。ゲームの調整値ではなく、動きの見え方で決めた仮の数字。
- **立ち強の内容**。ピスケは前蹴り、ゴダンは右のストレートとした。

## 既知の問題

- 元絵に横向きの資料がないので、横顔が元絵の印象と合っているかは確かめようがない。特に鼻先の長さと耳の位置。
- マーモット体型のまま手足を短くしているので、リーチが短く、歩きの脚の動きが小さい。
- 足と爪の描き込みが粗い。後ろ足は胴体と尻尾に重なって形が読みにくい。
- 構え用の拳は、横向きの拳を 90° 回した写し。握りの向きまでは描き分けていない。手の甲に指の筋は描いておらず、遠い手の親指は下半分にあるが、拳の大きさが 12〜17 px なので親指は「明るい帯」程度にしか見えない。
- 立ち強で肩を前へ送る表現は、胸のひねりの代わり。胴体をひねった絵は用意していない。
- ピスケの前蹴りは、足裏を見せる絵がなく、脚と足を回しただけ。腰の反りも硬い。
- 遠い側の腕は頭と胴体の後ろに描くので、高い位置へ出すと隠れる（しゃがみ弱の追加時に実際に起きた）。
- しゃがみで手を地面につくのはモグゾーだけ。ピスケとゴダンは構えの腕のまま。
- 表情の差分は最小限。耳は骨があるだけで、どのモーションでも動かしていない。
- 揺れ物（ハチマキ、帯、尻尾）は簡易な物理で、絵の更新のたびに形が変わる。意図したコマ割りにはなっていない。
- 歩きは絵の更新が 3〜4 フレームごとなので、ゲーム側が毎フレーム等速で動かすと、コマの間に最大 0.75〜2.25 px の見かけの揺れが出る（`docs/validation.md` の補足の表）。
- **動画としての再生は自分では見ていない。** 確認したのは静止画（全コマのコンタクトシート、比較画像、ビューワーのスクリーンショット）と数値。テンポや緩急の良し悪しは、ビューワーか GIF で見て判断してほしい。

## 検証のしかた

- `node tools/validate.mjs` が `docs/validation.md` を書き出す。足滑り、モーション間の高さと足元原点、体格比、IK の警告、セルのはみ出しを測る。
- `node tools/browser-check.mjs` は、ブラウザで描いた全コマと Node で描いた全コマのハッシュを比べる。Playwright がある環境で、リポジトリ直下から配信した状態で使う。この実験の最終状態では全コマ一致、コンソールエラーなしだった。
