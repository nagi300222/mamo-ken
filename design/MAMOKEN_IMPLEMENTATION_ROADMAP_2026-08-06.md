# マモ拳 実装ロードマップ — 2026-08-06

## 0. 目的

T00〜T20で整備した決定論的Core、現行3キャラ、スマホ縦画面、9体ロスター、正式3Dアートを土台に、ZIP／確定版キャラクター設計書で決まっている性能・技・UIを取りこぼさず実装する。

このロードマップでは新しい性能案を勝手に追加しない。既存資料の確定事項を先に構造化し、ダメージ・フレーム・受付猶予など明示的にBAL調整へ残された項目だけを実機検証で決める。

## 1. 正本優先順位

1. ユーザーが現在のチャットへ直接添付した画像と明示指示
2. 確定版 `マモ拳 キャラクター設計書 v1.0`
3. ZIP内の `01_CURRENT_DECISIONS.md` と統合設計資料
4. Combat / Battle / Command / Gauge / Damage / Frame Bible
5. Character Bibleと各キャラ文書
6. 現行実装と監査レポート
7. 古いテンプレート・候補・LEGACY記録

相違がある場合、上位の正本を優先する。

## 2. 現在地 — T20完了

- オフラインのキャラ選択は3×3で、9体を閲覧可能。
- 現在対戦可能なのはモグゾー／ピスケ／ゴダンの3体。
- 新6体は正式3Dアート採用・戦闘実装待ち。
- オンラインは現行3体のまま。
- 現行3体は各3コマンド技を実装済み。
- 確定版設計では、全9体が基本7技＋特殊能力1〜2個、咆哮、奥義を持つ。
- T20のCoreロスター契約には、型・能力名・奥義名・体格・アート状態までを登録済み。
- 基本7技、入力、属性、Reach、用途、難度、表示ステータス、コンボ、CPU性格の完全取り込みは未実施。
- 画像生成停止中。既存画像の利用、コード、データ、UI、テスト、BAL作業のみ進める。

## 3. 固定設計

- 通常8キャラ＋アナザー1キャラ。
- 全キャラがHIGH／MID／LOW／GRABを最低1つずつ持つ。
- Reachは0〜3。
- Reach 3技には最低2つ以上の代償を持たせる。
- 入力難度は受付猶予を極端に狭くして作らない。
- 基本は各キャラ7コマンド技＋特殊能力1〜2個。
- ギュイーンは全キャラ完全公平。固有能力、ステータス、連勝補正を乗せない。
- ダークモグゾーの対人CharacterDefとCPU用BossRuleSetは分離する。
- ダメージ、startup、active、recovery、hitAdv、guardAdv、入力受付猶予はBAL／実機調整項目。
- `handDigits = 4`、`footToes = 4`。
- 未実装キャラへ既存キャラの技・BAL・スプライトを仮割り当てしない。

## 4. キャラ選択から閲覧する情報

キャラ選択でキャラをタップした後、スマホ向け詳細パネルを開く。

### 4.1 タブ構成

#### 性能

- キャラクター名、種、スタイル
- 一言コンセプト
- 勝ち筋
- 弱点
- ATK／SPD／DEF／TEC／BRK
- 操作・判断難易度
- 固有能力
- 咆哮
- 奥義
- 現在の実装状態

#### わざ

- 基本7技
- 特殊技／条件派生
- 技名
- 方向入力＋上段／中段／下段／つかみ
- HIGH／MID／LOW／GRAB
- Reach 0〜3
- 主な用途
- 入力難度
- 実装状態: 実装済み／設計確定・未実装／BAL検証中

#### コンボ

各キャラ5本を次の分類で表示する。

1. 初心者
2. 基本
3. 実戦
4. 上級
5. 最大／条件付き最大

表示項目:

- コンボ名
- 入力列
- 始動条件
- 消費リソース
- 想定用途
- 実測ダメージ
- 実装・検証状態

MoveSpec実装前、または実機で連続成立を確認していないルートは「未検証」と表示する。確定コンボのように見せない。

### 4.2 スマホUI条件

- キャラ選択の3×3グリッドを維持。
- 詳細はボトムシートまたは全画面パネルとして開く。
- 「性能／わざ／コンボ」はタブで切り替える。
- 戻る操作で選択位置を保持する。
- 320×568〜430×932を検証対象にする。
- 一覧は縦スクロール可能。
- タップ領域は44px相当以上。
- 色だけで実装状態や属性を伝えない。
- 新6体の詳細は閲覧可能だが、対戦開始ボタンは無効のまま。

### T21 — 確定キャラクター性能の完全取り込み

目的: ZIP／確定版設計書を、機械検証可能なCoreデータへ変換する。

実装:

- 9体分の基本7技を構造化。
- 技名、入力、HIGH／MID／LOW／GRAB、Reach、役割、難度を登録。
- 特殊能力1〜2個、咆哮、奥義を登録。
- 勝ち筋、弱点、表示ステータス、操作難度、CPU方針を登録。
- 確定／BAL調整／未決をフィールド単位で区別。
- 現行3技をモグゾー／ピスケ／ゴダンの技枠1〜3へ対応づける。
- ZIP資料とT20簡易ロスター契約の差分監査を追加。
- 5コンボ枠のデータ型を追加するが、未実測ルートは未検証状態とする。

完了条件:

- 9体 × 7技 = 63技が重複なく登録される。
- 全キャラが4属性を最低1つ持つ。
- Reach 3技の代償メモが検証可能。
- 現行3体の既存コマンド名・入力が変わらない。
- 全キャラに5コンボ分類枠が存在する。
- ゲーム挙動は変更しない。

## 7. PR分割原則

- 1PRで「データ取り込み」「UI」「戦闘権限」「オンラインschema」を同時に変更しない。
- 新キャラは原則1体1PR、または共通機構1PR＋キャラ接続1PR。
- Core純粋関数 → runtime shadow/canary → オフライン権限 → オンライン権限の順を守る。
- 未決値を確定値としてコードへ埋めない。
- 各PRで現行3体、24 phase、7 flow、9既存command、BAL、ギュイーン公平性、server非変更を回帰確認する。
