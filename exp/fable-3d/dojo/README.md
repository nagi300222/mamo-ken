## v0.6 専用ステップ（2026-11-21）
本人のスマホ操作フィードバックを反映：**8方向スティックのすぐ下に「後ステップ」「前ステップ」を横並び**で追加。
- **後ステップ**：現在の向きから相手と逆方向へ18Fのステップ。ヨミカゲのジャストステップも可能。
- **前ステップ**：現在の向きから相手へ向かって18Fのステップ。
- スティックを離しても、押した瞬間のボタンが効く。短いタップは入力バッファで保持し、多点同時押しに対応。方向を2回倒す従来の操作も残す。
- キャラを飛び越えて向きが反転すると、前後ステップの方向も自動反転する。スティックを逆に倒していても専用ボタンの指定を優先。
- 左右の操作レール幅・中央ステージ・v0.3のカメラ・ジャンプ・右5ボタンは変更しない。
- PC: `F`＝前ステップ、`R`＝後ステップ。従来の`C`ステップと方向2回入力も引き続き利用できる。

## v0.2 スマホ試遊フィードバックに基づく現行操作（2026-11-21）
**現行仕様。以下のv0.1表記より優先。**
- 横画面の**中央は対戦表示のみ**。左レールに8方向スティック、右レールに丸ボタン5つ（弱・強・掴み・咆哮・ギュイーン）。ボタンとキャラが重ならない。左スティックと右ボタンは別PointerIdで同時押し。
- **専用必殺ボタンはない**。全9キャラ共通：236＋弱/強＝波動、623＋弱/強＝昇龍、214＋弱/強＝竜巻、236236＋強＝奥義（スーパー100必要）。右向き/左向きを自動認識。斜め入力省略・短縮受付あり。技の性能/名前は各キャラの仮実装で、今後個性化する。
- PC：方向＝矢印/WASD、弱＝Z、強＝X、掴＝V、咆哮＝B、ギュイーン＝N。方向2回で前後ステップ。スマホではスティックをすばやく2回倒す。
- **咆哮（ドライブ35消費）**：発生中に通常技・飛び道具を受け止め、相手へ打撃。飛び道具を消す。後から咆哮で返せる。
- **ギュイーン（ドライブ60消費）**：攻撃中やダメージ受け止め中にも使える超装甲の前進。相手に接触すると両者が取っ組み合って、一時的に攻撃不能となり、HPを減らさず距離を離してニュートラルに戻る。遠距離空振りの場合もドライブは消費する。
- ジャンプの頂点を全キャラとも相手の頭上を越える高さに設定。空中左右移動によって前後の位置と向きが入れ替わる。別の奥行きレーン移動機能ではない。
- GLBは現行の共通10＋固有1のまま。咆哮/ギュイーン/専用やられモーションは**ゲーム処理を実装済み、完成アニメは未納品のため代用クリップ表示**。Claude向け[追加Issue #148](https://github.com/nagi300222/mamo-ken/issues/148)。
- バランスは仮値。スマホ実機での操作性とCloudflare Pagesのデプロイ成功は、コード上のテストだけでは証明できない。

## Windows / Macでローカル実行
Node.js 20以上、WebGL2対応のブラウザ。依存追加不要。

リポジトリのルートから:
```bash
cd exp/fable-3d/dojo
npm test
npm start
```
ブラウザ: `http://127.0.0.1:4173/exp/fable-3d/dojo/`

PC操作: 矢印またはWASDで移動とジャンプ/しゃがみ、Z弱、X強、V掴み、B咆哮、Nギュイーン、Cステップ。後ろ方向でガード。方向キー2回で前後ステップ。必殺は**方向コマンド＋ZまたはX**（236=波動、623=昇龍、214=竜巻、236236+X=奥義）。

スマホ: **左の8方向バーチャルスティック**をドラッグ（上下左右・斜め）、右の**弱／強／掴み／咆哮／ギュイーン**を押す。どちらも対戦画面の左右端へ重ね、中央を広く表示。複数の指で同時入力可。コマンドは前後反転・斜め抜け短縮を許容。9GLBを一括転送せず対戦2体のみ読み込む。

## Cloudflare Pages
まず最小アセットのみ出力:
```bash
npm run build:pages
```
リポジトリルートからでも `node exp/fable-3d/dojo/build-pages.mjs` で同じ。出力は `exp/fable-3d/_pages/`。9GLB、Three.jsローカルモジュール、選択画像、ゲームコードだけを含み、元の動画や.blendは配信しない。

**Cloudflare Pages Git連携の場合**：
- GitHub: `nagi300222/mamo-ken`
- プレビュー対象ブランチ: `feat/mamoken-3d-mobile-fight`
- ビルドコマンド: `node exp/fable-3d/dojo/build-pages.mjs`
- ビルド出力ディレクトリ: `exp/fable-3d/_pages`
- ルート `/ `から`/dojo/`へ自動案内。キャラ選択後に対戦可能。
- 実際のプレビューURLはCloudflareにビルド結果が存在してから確認すること。GitHub PRがあるだけではデプロイ済みと扱わない。

**Wrangler Direct Upload**（Cloudflareに認証済みで既存Pagesプロジェクト名が分かる場合）:
```bash
npx wrangler pages deploy exp/fable-3d/_pages --project-name <既存Pagesプロジェクト名> --branch feat/mamoken-3d-mobile-fight
```
Cloudflareアカウント認証とアップロード権限が必要。<プロジェクト名>は例ではなく実名に置き換える。GitHub Actionsのプレビュー自動アップロードは`CLOUDFLARE_API_TOKEN`・`CLOUDFLARE_ACCOUNT_ID`のSecretsと`CLOUDFLARE_PAGES_PROJECT`の変数がある場合のみ動作。

## モデル差し替え（造形修正後）
**ゲームロジックを変更せず**差し替え可能。
1. `exp/fable-3d/chars/<id>/<id>.glb` を新モデルへ更新する（同じIDとクリップ名を推奨）。
2. 必要なら `<id>_motions.json` も更新。バレットの尾先端軌道が変わる場合は、JSON の `sp_tail_whip.tail_tip_path` を新造形から再測定する。対戦開始時に自動で軌道を読み込み、尻尾判定に使う（`balance.js` の手編集は不要）。
3. `dojo/models.js` の `MODEL_REVISION` を更新してキャッシュを更新。
4. `npm test` → `npm run build:pages` → Cloudflareプレビューで差し替え確認。

強攻撃等のアニメ名の対応表は `models.js` にあり、GLB側に専用モーションがない場合は既存クリップを仮流用する。造形修正が技フレーム・ダメージ・判定へ勝手に影響しない設計。
