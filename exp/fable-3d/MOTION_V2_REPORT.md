# モーション拡張 v2 報告（Issue #147 / #148）

ブランチ `exp/mamoken-fable-3d-motion-v2`（`exp/mamoken-fable-3d-roster9` 起点）。変更は `exp/fable-3d/` 以下だけで、ゲーム本体（PR #143 の `dojo/`）は編集していない。

## 結論

- 9体すべてに、**追加クリップ26本**（moguzo は27本の枠のうち26本、他8体も26本。内訳は下）を上乗せした。1体あたりのクリップは 11 → 37 本。
- **造形・リグ・ボーン名・足元原点・身長比・既存11クリップは変えていない。** 既存11クリップは、9体とも全ボーン位置が拡張前と一致（差 0）。バレットの `sp_tail_whip` の尻尾先端軌道（`tail_tip_path`）も同一。
- 優先順どおり、**第1段＝咆哮・ギュイーン3段階・ガード・弱強被弾・ダウン/KO・掴み/投げ**、**第2段＝しゃがみ/空中の通常技とコマンド技・奥義**の順で作り、コミットも分けてある。
- 組み合い（`clinch_hold`）は、**全81通りの組み合わせ**で両者の手のひらが同じ位置に来る（ずれ最大 2.4cm）。体格差の大きい組（chirka と takimaru など）でも成立する。
- これは「ゲームに差し込んで動きを比べられる初版」。技名・フレーム・性能はすべて仮の値で、演出として採用が確定したものは無い。

## ゲーム側（`dojo/models.js`）の接続点

ゲームコードは編集していない。Codex が差し替えるときの案を示す。

**そのまま拾われるもの**（PR #143 の `chooseClip` が既に名前を探している）:
`roar`、`gyuiin`、`clinch_hold`、`clinch_recoil`、`roar_hit`、`hurt_heavy`、`guard_hit`、`guard_crouch_hit`、`guard_impact`、`throw_reach`、`ko`、`down`。

**名前の対応を足すと使えるもの**:

| 変更箇所 | 案 |
|---|---|
| `FALLBACK_CLIPS` | `crouch_weak:'crouch_light'`、`crouch_heavy:'crouch_heavy'`、`air_weak:'air_light'`、`air_heavy:'air_heavy'` に差し替え（無ければ従来の `stand_*` へ落とす） |
| `balance.js` の通常技の `anim` | `crouch_weak` / `crouch_heavy` / `air_weak` / `air_heavy` の `anim` を上と同じ名前に |
| 必殺技・奥義の `anim` | `{id}_motions.json` の `command_map` を読んで `236`→s1、`623`→s2（対空）、`214`→s3、`236236`→奥義に割り当てる。現在は全部 `sp_*` を使い回している |
| しゃがみガードの保持 | `state==='block'` かつ下入力のとき `guard_crouch` を選ぶ（今は `guard_stand` のみ） |
| 投げ成立 | つかんだ側に `throw_hit`、つかまれた側に `thrown` を同じフレームで再生（今は投げ成立の状態が無い） |
| ダウンと起き上がり | `down`→`wakeup` の状態を作るなら使える。`ko` は最後の姿勢のまま止まる |
| 着地・ダッシュ制動・バックダッシュ | `land`、`dash_stop`、`dash_b`。対応する状態ができたら割り当てる |

**始めの姿勢に注意が要るクリップ**: `guard_hit` / `guard_impact` は立ちガードの保持姿勢から、`guard_crouch_hit` はしゃがみガードの保持姿勢から、
`crouch_*` はしゃがみの保持姿勢から、`air_*` と `land` は空中姿勢から始まる。直前に対応する保持クリップを再生していれば、0.05秒前後のクロスフェードで自然につながる。
各クリップの `start_pose` / `end_pose` に書いてある。

**ゲーム側の演出との重なり**: `main.js` は咆哮・組み合い・被弾・ガードで、モデル全体に拡大（`scale`）と傾き（`rotation.z`）をかけている。
今回のクリップは姿勢そのものに踏み込み・のけぞり・押し合いを入れたので、両方かけると動きが二重になる。新クリップがあるときは、その追加の傾きと拡大を弱めるか外すことを勧める。

**組み合いの位置**: ゲームは2体を 0.36m 間隔に置く。`clinch_hold` はその間隔を前提に、各自の原点から前へ 0.175m・高さ 0.33m で手のひらを合わせる（`pair_spacing_m`、`palm_contact_m` に記録）。
間隔を変えるなら、`motions_v2.py` の `CLINCH` の値を変えて作り直す。

## 課題一覧

自動検証では分からないもの、目で見て残っているものを書く。**演出として完成・採用確定のものは無い。**

### 共通

| 種類 | 状態 |
|---|---|
| 口 | 開かない。咆哮は `jaw` を最大まで下げているが、あごが少し下がるだけで口の中は見えない。咆哮の「吠えている」感じは体の動きとゲーム側の衝撃波に頼っている |
| 接地 | 寝た姿勢は体格から腰の高さを決めているが、背中の毛の厚みぶん床に少し沈む／浮く個体差がある。尻尾は体の横（本人の右）へ倒して床に置くが、太さの半分ほど（ボーン位置で5〜7cm）床に沈む |
| 交差・貫通 | 手や腕と体の貫通は自動で検出していない。ガード系は両手が顔の前で重なる。`throw_hit` の抱え上げは相手との位置合わせをしていない（相手側 `thrown` は高さだけ合わせた目安） |
| 装飾 | ハチマキ・帯の垂れは倒れたとき床を突き抜けることがある（バネで揺れるだけで、床との当たりは無い）。hakuma のスカーフ、takimaru の縄は体に追従するが、深い前傾で体に食い込む |
| 空中技 | 上下移動を含まないので、単体で見ると地面で足を上げているように見える。ゲーム側でジャンプの高さと組み合わせて初めて成立する |
| 緩急 | キーポーズ間の補間で作った初版。ヒットストップや画面揺れと合わせた調整はしていない |

| クリップ | 残っている点 |

## 未完成・未確定

- 技名、発生・持続・硬直、多段のヒット区間、移動量は仮の値。ゲーム側の `balance.js` の数値とは一部ずれている（クリップの長さは見た目優先で決めた）。

- ゲーム本体に組み込んだ状態での確認はしていない（担当外）。`preview/versus.html` で 2体を同じ間隔・同じ向きに置いて代用した。
