# 報告：マモ拳 3D 全9キャラ初版（roster9）

正本は [Issue #140](https://github.com/nagi300222/mamo-ken/issues/140)。ブランチ `exp/mamoken-fable-3d-roster9`（main は未変更、変更は `exp/fable-3d/` 以下のみ）。
3体だけだった時点の報告は [docs/REPORT_3chars_2026-11-21.md](docs/REPORT_3chars_2026-11-21.md) に残してある。

## 結論

- **9体すべてが、共通10モーション＋固有モーション1つ入りの GLB として再生でき、並べて比べられる状態になった。** 自動検証は9体とも全項目合格。
- **バレットには、長い尻尾（6ボーン）を実際に振って当てる長リーチ打撃を入れた。** 尻尾先端の最大リーチは 0.65m で、バレット自身の最長のパンチ（0.41m）の 1.58 倍。先端の軌道はモーションJSONに記録してある。
- **これは「3D初版の合格」であって「造形の完成」ではない。** 9体は体格・配色・装飾で見分けがつくが、顔の作りは共通部品のままで、元絵の顔つき・毛束・ヒゲには届いていない。キャラ別の不足は下の一覧に書いた。
- 既存3体（moguzo / pisuke / godan）の共通10モーションは、回帰チェックで拡張前と全ボーン位置が一致（差 0）。変えたのは固有モーションの追加だけ。

固有モーションの技名・フレーム・性能、身長、バレットの尾打撃の弱点づけは、**すべてAIの仮案で本人未確定**。

共通10モーション（idle, walk_f, walk_b, dash_f, crouch, jump_n, stand_light, stand_heavy, guard_stand, hurt_light）は同じ記述を使い、

## バレットの長尾攻撃（個別確認）

`validation/deform/bullet_E_tail_whip.jpg`（横・真上・斜め・後ろの4視点を8フレーム分）と `chars/bullet/motions/sp_tail_whip.mp4` で確認できる。

| 項目 | 結果 |
|---|---|
| 尻尾の骨 | `tail_01`〜`tail_06` の6本（他キャラは3本）。付け根は骨盤からなめらかにつながる |
| 動きの読みやすさ | 尻尾を反対側へ巻く溜め（F8〜10）→ 小さく跳んで体を回す（F10〜16）→ 尻尾が水平に前へ伸びる（F19〜25）→ 戻り。横視点で尻尾が画面右へ伸びるのが読める |
| 最大リーチ | 尻尾先端が原点から前へ 0.651m（F24、高さ 0.25m）。持続に設定した F19〜25 の中にある |
| 拳との比較 | 最長のパンチ（強攻撃 0.412m）の 1.58 倍。GLB上でも最大リーチのボーンは `tail_06` |
| 接地との干渉 | 尻尾先端の最低の高さは 0.158m。床には触れない |
| 胴との貫通 | 尻尾（3本目以降）と胴の軸の最小距離は 0.234m。胴の半径（約0.14〜0.17m）より外で、胴には潜らない |
| 当たり判定との対応 | 先端の軌道を `bullet_motions.json` の `tail_tip_path`（2Fごと、前・左・高さ）に記録。判定は実際の尻尾の位置に置ける |

注意点と仮案:

- 体の回転（F16〜21）に対して尻尾は約3フレーム遅れて届く。持続区間はこの実測に合わせた。
- 振る間は相手に背を向ける。発生19F・全体48Fと遅い。尻尾の付け根側は当てない想定にして近距離の弱点にする、というのが**AIの仮案**（`proposal` に記載）。採用値ではない。
- 足は小さく跳んで踏み替える。踏み替え中の両足の交差は見た目で確認しただけで、脚どうしの貫通の自動チェックは無い。
- 尻尾と自分の脚の接触は検証していない（胴の軸からの距離だけ見ている）。
- 共通モーションでの尻尾: 待機ではS字に持ち上げ、歩き・ダッシュ・被弾では遅れて揺れる。しゃがみとジャンプで尻尾が床や体に触れるかは個別に見ていない。

自動で確かめている項目:

- スキンが1つあり、必須ボーン（30本）がすべてある。全頂点に JOINTS_0 / WEIGHTS_0 があり、ウェイト合計が1（最大4影響）。
- シェイプキー4種（`paw_open.L` / `paw_open.R` / `blink` / `brow_angry`）がある。
- 共通10クリップ＋固有モーションがあり、長さが定義と一致する。
- Three.js（GLTFLoader + AnimationMixer）で全クリップを読み込み、全クリップでボーンが実際に動き、コンソールエラーが無い。
- ループの継ぎ目が合う。単発クリップは idle の姿勢へ戻る（本体ボーンの差 0）。尻尾・垂れ布は終端で収束する。
- 足のボーンが床より下へ行かない。しゃがみでリード手が床につく。
- bullet: 尻尾が5本以上、尾打撃の最大リーチが尻尾によるもので拳の1.35倍以上、持続区間内、床と胴に潜らない。

別に確かめたこと:

- 既存3体の回帰チェック（`tools/regress.mjs`）: 共通10クリップの全ボーン位置が拡張前と一致、メッシュの頂点数・三角形数も同じ。
- プレビューの操作（`tools/ui_check.mjs`、`validation/preview_ui.json`）。
- 変形の目視確認: `validation/deform/{id}_A〜D.jpg`（9体×4枚）。腕を前・頭上、脚上げ、拳の回転、しゃがみ→ジャンプ、攻撃と復帰、尻尾と装飾、固有モーション。

**自動検証で分からないこと**: 元絵に似ているか、動きが気持ちいいか、装飾と体の貫通、指や顔の細部。「関節エラー0＝造形の合格」ではない。

## モーションの課題

- 共通モーションは同じ記述の数値違いなので、歩き・ジャンプ・被弾はキャラ間で似て見える。重量級（godan / hakuma / takimaru）の「重さ」は、待機と歩きの遅さ、ダッシュとジャンプの鈍さで出しているだけ。
- 歩きは短い脚なりの小さなすり足。
- 固有モーションは「何をしているか読める」水準で、緩急や見栄えは詰めていない。takimaru の抱え込みはつかむ所まで（投げ動作は無い）。yomikage の受け返しは構えと反撃のみ（成立条件はゲーム側）。
- 多段技のヒット区間、アーマー区間、カウンター受付区間、移動量はJSONに入れたが、すべて仮の値。
- 体格の大きい hakuma は、しゃがみでリード手が床にぎりぎり届く（手のボーン高さ 4.3cm、判定しきい値 4.5cm）。

## 次の段階（フェーズC）への引き継ぎ

- 最初に直す価値が高いのは共通の顔部品（目・まぶた・眉・マズル）とヒゲ、次に毛束、その次に股関節まわり。ここは9体に一括で効く。
- 顔と毛束は、今の SDF の足し合わせでは限界がある。リグとウェイト計算は残して、顔・毛束・装飾を専用メッシュとして合成する方向（Issue #140 フェーズA-1 の方針）が現実的。今回はそこまで手を付けていない。
- モデルの編集とモーションの生成はコード上で分かれている（`characters.py` / `body.py` / `texture.py` と `motions.py` / `anim.py`）。造形を直してもモーション定義はそのまま使える。
- ゲーム本体（`src/`）や `feat/threejs-reimagined-mamoken` への統合はしていない。
